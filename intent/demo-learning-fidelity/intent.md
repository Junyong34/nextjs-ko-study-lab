## Problem

학습자가 안내를 따라 실행해도 주제에 해당하는 Next.js 동작을 관찰하지 못하거나 검증 결과가 갱신되지 않는 예제가 있다. 사용자가 지정한 5개 페이지의 소스를 검토한 결과는 다음과 같다. 브라우저 재현과 런타임 오류 검사는 아직 실행하지 않았다.

| 페이지 | 소스에서 확인한 문제 | 제안 방향 |
|---|---|---|
| `/demo/components/form-component` | `FormSearchClient.tsx`는 `next/form`을 사용하지 않고 `preventDefault()`와 React 상태로 검색한다. 서버 검색과 URL 변경이라는 안내와 다르다. `VerificationFooter`에 관측값을 전달하지 않는다. | 실제 `next/form` 제출과 서버 `searchParams`로 다시 구성한다. 빈 검색, 일치, 결과 없음, 재검색을 제공하고 iframe 내부 URL과 서버가 읽은 값을 표시한다. |
| `/demo/file-conventions/parallel-routes` | 실제 `@analytics`, `@team` 슬롯이 있으나 가이드는 `@feed`를 설명한다. 슬롯 이동 조작이 없고 검증 패널은 관측값을 받지 않는다. 실제 로딩·오류 경계 파일 없이 독립 로딩·오류 처리를 검증한다고 설명한다. 고정 통계를 실시간처럼 표시한다. | 실제 슬롯 이동, 다른 슬롯의 상태 유지, 새로고침 시 기본 화면을 비교하도록 재구성한다. 설명하는 로딩·오류 격리를 구현하거나 설명 범위를 줄인다. 예시 데이터와 관측 결과를 구분한다. |
| `/demo/architecture/accessibility/form-aria-support` | 실제 DOM 속성을 읽지만 설명 대상 ID가 기대한 ID인지 비교하지 않는다. 숫자를 16자리로 자른 뒤 길이를 검사해 초과 입력도 유효하게 처리한다. 안내는 재제출을 요구하지만 첫 제출 이후에는 입력 즉시 판정이 바뀐다. | 빈 값, 짧은 값, 정상, 초과 입력, 오류 수정, 초기화를 다룬다. 연결 ID와 실제 설명 문구, label 연결을 확인한다. React·HTML 접근성 예제라는 범위를 명확히 한다. |
| `/demo/architecture/server-action-security/csrf-protection` | 실제 Server Action과 요청 헤더를 사용한다. 다만 정상 요청 도달만 관측하며 다른 출처 요청의 차단을 재현할 절차가 없다. | 동일 출처 허용과 출처 불일치 차단을 실제 프레임워크에서 비교한다. 배포 페이지에서 안전하고 재현 가능한 구성을 확인하고, 불가능하면 로컬 절차를 제공한다. 정상 요청 도달을 전체 CSRF 검증 성공으로 표시하지 않는다. |
| `/demo/architecture/turbopack/incremental-harness` | 환경값과 카운터는 읽지만 검증 성공 조건은 환경값뿐이다. 소스 변경이나 상태 보존을 검사하지 않는다. 배포 화면에서 핵심 절차를 수행할 수 없다. | 로컬 개발 실습으로 전환한다. 환경 확인과 소스 갱신 관측을 구분하고 프로덕션에서는 실행 불가를 표시한다. 로컬 안내를 수용할 수 없는 공개 운영 구조라면 실행 데모에서 제외하고 문서로 옮긴다. |

근거 파일은 `nextjs-app/apps/demo-baseline/src/app/zone/baseline/` 아래 각 페이지의 `page.tsx`, `layout.tsx`, `components/`, CSRF의 `actions.ts`다. `nextjs-app/docs/09-demo-status-and-stepwise-release-guide.md` 6절에도 접근성·CSRF·Turbopack의 브라우저 검증 보류와 빌드 중단이 기록돼 있다. 과거 타입 검사 통과를 이번 동작 검증으로 간주하지 않는다.

## Proposed outcome

학습자가 실행 절차를 따라 조작하면 주제와 연결된 실제 변화가 나타나고 검증 패널에서 기대 결과와 관측값을 비교할 수 있다. 초기 상태, 실행 중, 성공, 불일치, 실행 불가를 혼동하지 않는다. 정상 사례뿐 아니라 실패와 복구도 직접 확인할 수 있다.

웹에서 관찰 가능한 Form과 병렬 라우트는 재구성한다. 접근성은 유지하면서 입력과 검증을 보완한다. CSRF는 허용·차단 비교를 확보하고 Turbopack은 로컬 실습 중심으로 전환한다. 삭제는 주제 자체가 아니라 실행 가능성과 학습 효과를 기준으로 결정하며, 제외할 경우 문서 대체와 기존 링크 처리를 함께 정의한다.

안내 문장은 korean-humanizer 기준으로 번역체와 불필요한 영어 병기, 추상적인 표현을 다듬는다. 예를 들어 'DOM 계약'은 실제 속성과 연결 대상 설명으로, 'searchParams 실제 바인딩 값 대조'는 '서버가 읽은 검색어 확인'으로 바꾼다. 단순 윤문과 잘못된 기술 설명 수정·신규 안내 작성을 구분하고, 사실을 보존해야 한다는 윤문 규칙으로 기존 오류를 남기지 않는다.

## Affected users and systems

- 사용자: 배포 사이트에서 실습하는 학습자, 저장소를 내려받아 로컬 개발 실습을 하는 학습자.
- 시스템: 위 5개 baseline 라우트, 필요한 데모 등록 항목과 연결 문서, 해당 기능 테스트와 공개 운영 기록.
- 병렬 라우트의 기존 하위 예제는 부모 layout 변경의 회귀 점검 대상이다. 별도 페이지의 전면 개편은 포함하지 않는다.

## Constraints

- 실제 Next.js 기능을 사용한다. 고정 데이터는 예시로 쓸 수 있지만 요청 결과, 성공 여부, 성능, 라우팅 상태를 꾸미지 않는다.
- 기존 4단 실습 구조와 zone 경계를 지킨다. 검색 URL은 iframe 내부 동작으로 한정하고 외부 학습자 URL에 실습 상태를 남기지 않는다. 공통 URL 상태 규칙과 충돌하는 부분은 spec에서 해석과 필요한 예외를 명시한다.
- 설치된 기준 버전의 공식 문서와 구현을 확인해 설명을 검증한다. ARIA DOM 검증을 스크린 리더 사용성 전체 검증으로 표현하지 않는다.
- CSRF 차단 재현을 위해 실제 데이터 변경이나 보안 설정 완화를 도입하지 않는다.
- Turbopack의 환경값이나 React 카운터만으로 증분 빌드 성능을 입증하지 않는다. 임의의 시간 수치를 만들지 않는다.
- 제거·공개 상태 변경 시 demos.yaml을 기준으로 관련 목록과 링크를 함께 정리한다. 생성 파일을 수동 편집하지 않는다.
- 구현 완료 판단에는 가이드 전 단계의 브라우저 실행, 여러 입력 사례, 검증 패널 갱신과 초기화, 콘솔·서버 오류 확인, 관련 검사와 빌드 결과가 필요하다. 실행하지 못한 검사는 별도 기록한다.
- 범위 밖: 전체 데모 일괄 개편, Next.js 버전 변경, 배포 실행, 일반적인 결제 유효성 검사 시스템 구축.

## Open questions

- 제안: Turbopack은 배포 화면에서 로컬 실행 안내를 제공한다. 실행 화면 유지 여부는 spec에서 공개 운영 방식과 함께 확정한다.
- CSRF 차단의 브라우저 재현 방식과 셸 프록시의 Origin/Host 처리는 spec 단계의 읽기 전용 조사로 확인한다. 불일치 요청 차단을 앱 내부 모의 판정으로 대체하지 않는다.
- 2026-09-08 사용자에게 intent 방향 승인을 받았다. spec 방향 승인 요청에 이어 plan 사전 검토안을 작성했다. PR 머지와 plan 승인은 아직 없으며 구현 승인으로 간주하지 않는다.
