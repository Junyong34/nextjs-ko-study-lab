## Requirements

### 공통

- 가이드, 실습 화면, 검증, 개념 정리의 4단 구조를 유지한다. 실행 절차는 실제 입력·버튼과 일치하고 관찰할 위치를 알려준다.
- 검증은 관측한 범위만 판정한다. 초기·관측 전 상태를 실패로 표시하지 않고 환경 확인을 기능 검증 완료로 확대하지 않는다. 초기화와 재실행 때 오래된 결과가 남지 않는다.
- 예시 데이터는 허용하되 예시임을 알린다. 요청 결과, 라우팅, ARIA 속성, 성능 결과는 고정값으로 꾸미지 않는다.
- korean-humanizer로 어색한 표현만 다듬는다. 기술 오류 수정·신규 안내 작성은 단순 윤문과 구분한다. 'DOM 계약', '실행 경계에 도달' 같은 표현은 구체적 동작으로 풀어 쓴다.

### Form

- 실제 `next/form`의 문자열 action과 이름이 있는 입력을 사용한다. 제출을 막고 React 상태만 바꾸는 검색을 제거한다.
- 서버 페이지가 `await searchParams`로 읽은 검색어로 예시 상품을 필터링한다. 앞뒤 공백은 제거한다. 빈 검색은 전체, 없는 검색어는 0건으로 표시한다.
- 입력 중인 값과 제출한 값을 구별한다. 검증에는 iframe의 실제 경로·쿼리, 서버가 읽은 검색어, 표시한 상품 수를 제시한다.
- 공유 레이아웃에 사용자가 바꿀 수 있는 상태를 두어 제출 후 유지되는지 새로고침과 비교한다. prefetch와 JavaScript 미사용 동작은 별도로 확인하지 않았다면 자동 성공으로 표시하지 않는다.

### 병렬 라우트

- 실제 `@analytics`, `@team`, `children`을 사용하고 잘못된 `@feed` 안내를 없앤다.
- analytics에만 있는 상세 경로를 실제 `Link`로 연다. team의 현재 화면과 입력 상태가 유지되는지 관찰한다.
- 같은 상세 경로에서 iframe을 새로고침하면 일치하지 않는 team과 children의 `default.tsx`가 표시된다. 기본 화면은 원래 page를 그대로 재사용하지 않고 새로고침 후 대체 화면임을 알린다.
- 초기 진입, 슬롯 이동, iframe 새로고침, 처음으로 돌아오기를 제공한다. 선택된 슬롯 세그먼트와 실제 렌더링된 화면 식별값을 함께 읽는다. 클릭 여부만으로 성공 처리하지 않는다.
- 슬롯 조합과 이동·새로고침 차이에 집중한다. 구현하지 않은 로딩·오류 격리를 검증한다는 설명은 제거한다.
- 기존 `independent-tabs`, `conditional-slot`은 부모 layout 변경의 회귀 확인 대상이다. 가이드 중복과 404를 방지한다.

### 접근성 폼

- Next.js 앱 안에서 구현한 HTML·React 접근성 패턴이라고 설명한다. Next.js 고유 기능이 카드 입력을 검증한다고 주장하지 않는다.
- 숫자를 자르지 않는다. 숫자와 공백·하이픈만 허용하고 구분자를 제외한 숫자가 정확히 16개인지 검사한다. 카드 진위나 결제 가능 여부를 검사하지 않는 학습용 형식 검사임을 명시한다.
- 첫 제출 전에는 오류를 숨긴다. 첫 제출 후에는 입력을 고치는 즉시 다시 검사하고 안내도 이에 맞춘다.
- 빈 값, 짧은 값, 16자리, 초과, 문자 포함, 구분자 포함, 오류 수정과 초기화를 제공한다. 예시 값 채우기 버튼은 입력만 바꾸고 검증 결과를 직접 설정하지 않는다.
- 실제 input의 `aria-invalid`, `aria-describedby`, 연결된 ID·텍스트, label 연결을 확인한다. 설명 요소가 존재하기만 해도 성공하는 판정을 없앤다.
- DOM 검사를 스크린 리더 음성 출력 검증으로 표현하지 않는다. 키보드·보조 기술로 직접 확인할 내용을 구분한다.

### CSRF

- 배포 페이지에서는 실제 Server Action 정상 요청과 서버가 받은 Origin·Host·X-Forwarded-Host를 관찰한다. 판정 범위는 '정상 요청 실행 확인'이다.
- 차단은 로컬 개발자 도구에서 성공한 정상 요청을 복사한 뒤 Origin만 바꿔 재전송하는 절차로 제공한다. 대상은 자신의 로컬 서버이며 액션은 헤더 조회 외에 데이터를 변경하지 않는다.
- 액션 식별자나 요청 본문을 고정 예시로 만들지 않는다. Next.js 내부 요청 형식을 학습자에게 직접 조립하게 하지 않는다.
- 응답 상태와 프레임워크의 Origin 불일치 서버 로그를 함께 확인한다. 임의의 500 응답만으로 차단 성공이라 판정하지 않는다. 관측용 액션 도달 로그를 추가해 정상 요청과 차단 요청을 비교한다.
- 웹 패널은 로컬 차단 검사를 관측할 수 없으므로 자동 완료 표시를 하지 않는다. 현재 데모 요청만 복사하도록 안내한다.
- 셸 경유와 baseline 직접 요청을 확인한다. 기존 allowedOrigins는 셸 프록시용 예외라고 설명하며 실습 목적으로 확대하지 않는다. Origin 누락을 출처 불일치와 동일하게 다루지 않는다.

### Turbopack

- 기존 URL을 유지하고 로컬 개발 실습으로 표시한다. 배포 환경에서는 실행 명령, 저장소 기준 편집 파일 경로, 기대 결과를 제공한다. 배포 페이지에서 소스 수정 단계를 완료할 수 있다고 안내하지 않는다.
- 개발 환경에서는 카운터를 올리고 '비교 시작'으로 marker와 카운터를 기록한다. 실제 `hmr-marker.ts` 편집 후 문구 변화와 상태 유지를 비교한다. 비교 중 카운터 조작을 잠근다.
- 편집 전에는 대기, marker 변경과 카운터 유지가 확인되면 '문구 갱신·상태 유지 확인'을 표시한다. 새로고침으로 관측 기록이 사라지면 미관측 상태로 돌아간다.
- iframe 새로고침으로 카운터와 관측 기록이 초기화되는 것을 비교한다. Fast Refresh 관찰을 증분 캐시 전체나 성능 향상의 증명으로 설명하지 않는다.
- 서버·브라우저에서 다른 `import.meta.env.SSR`은 첫 HTML과 hydration 렌더에서 동일한 준비 상태를 표시한 뒤 브라우저에서 읽는다. 경고 억제로 오류를 숨기지 않는다.

## Design

5개 URL은 유지한다. Form과 병렬 라우트는 재구성하고 접근성은 보완한다. CSRF는 배포 관측과 로컬 차단 실습을 결합한다. Turbopack은 로컬 실습 중심으로 전환한다. 새 실행 서비스는 도입하지 않는다.

공통 `ExpectedActualPanel`은 isMatched가 undefined이면 문자열을 자동 비교한다. 대상 페이지의 미관측 상태에서는 ReactNode와 상태 안내를 사용해 자동 판정이 개입하지 않도록 한다. 공통 API 변경 없이 해결하며 실제 대기 상태를 확인한다.

`nextjs-app/apps/AGENTS.md` 7번의 URL 상태 금지에는 Form 검색 쿼리와 병렬 라우트 경로가 iframe 내부에서만 바뀌는 실습 예외를 명시하는 변경을 제안한다. 셸 URL에는 실습 상태를 복사하지 않고 새로 실습에 진입하면 초기 상태로 시작한다. 이 규칙 보완도 승인 대상이며 구현과 함께 반영한다.

`nextjs-app/docs/09-demo-status-and-stepwise-release-guide.md`에 로컬 전용 단계와 실행 증거를 구분해 기록한다. 등록 제목·설명에 실행 환경을 반영하고 demos.yaml에서 생성물을 갱신한다. 기존 공개 상태를 미실행 검증의 통과 근거로 삼지 않는다.

## 조사 근거

- 2026-09-08 next-devtools가 설치된 Next.js 16.3.2와 번들 문서 경로를 확인했다. 아래 경로는 `nextjs-app/apps/demo-baseline/node_modules/next/` 기준이다.
- `dist/docs/01-app/03-api-reference/02-components/form.md`: 문자열 action, GET 쿼리, 공유 상태 유지.
- `dist/docs/01-app/03-api-reference/03-file-conventions/parallel-routes.md`: soft navigation의 슬롯 유지, hard navigation의 default 처리, implicit children의 default 필요성.
- `dist/docs/01-app/02-guides/data-security.md`와 `dist/server/app-render/action-handler.js`: Origin 검사, allowedOrigins 예외, 누락 헤더 처리, 액션 실행 전 차단. 이 버전 fetch action의 차단 응답은 500이므로 403으로 단정하지 않는다.
- `dist/docs/01-app/03-api-reference/08-turbopack.md`: import.meta.env와 Fast Refresh 지원. 환경값은 소스 갱신 관측을 대체하지 않는다.
- 2026-09-08 포트 3001의 get_project_metadata로 현재 저장소 baseline 서버임을 확인했다. get_errors는 Turbopack 페이지에서 SSR true/false 차이의 hydration 오류를 반환했다. 기존 브라우저 세션의 진단이며 이번 작업에서 5개 페이지를 새로 순회한 결과는 아니다.
- 기존 `23-architecture-demo-authenticity.test.ts`는 소스 패턴을 검사한다. 통과만으로 실행 절차나 차단·상태 유지가 입증되지는 않는다.

## Non-goals

전체 데모 재설계, Next.js 업데이트, 배포, 결제 번호 진위 검사, 별도 악성 사이트·프록시 서비스, 번들러 성능 벤치마크, 웹에서 서버 파일 편집 기능은 범위 밖이다.

## Review

adversarial-document-reviewer로 관측과 결론의 관계를 점검해 다음 반례를 반영했다.

- CSRF의 500은 요청 형식 오류일 수도 있다. 정상 요청을 먼저 확보하고 Origin만 바꾼 뒤 프레임워크 차단 로그까지 확인한다.
- 환경값이 정상이어도 HMR은 일어나지 않을 수 있다. marker 변경과 이전 상태를 실제 비교하고 결론을 Fast Refresh 관측으로 제한한다.
- 속성 이름이 소스에 있어도 연결은 잘못될 수 있다. 렌더링된 ID·텍스트와 사용자 실행 흐름을 검사한다.

## Open questions

- 제안 내 미정인 제품 결정은 없다. 로컬 CSRF 차단과 Fast Refresh 재현은 구현 검증에서 확인해야 하며 문서 작성만으로 성공을 보장하지 않는다.
- 대화의 승인 의사를 바탕으로 파일별 plan 사전 검토안을 작성했다. 공식 단계 진입을 위한 PR 머지 기록과 plan 승인은 아직 없으며 구현은 시작하지 않았다.
