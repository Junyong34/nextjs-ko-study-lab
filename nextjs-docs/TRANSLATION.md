# 번역 규칙

Next.js 공식 영문 문서를 한국어 학습 문서로 옮길 때의 규칙이다. 작업 절차 전체는 [AGENTS.md](./AGENTS.md)에 있고, 이 문서는 그 중 **번역 품질**만 다룬다.

## 적용 범위

이 규칙은 다음 두 곳에만 적용한다.

- [AGENTS.md](./AGENTS.md) 「새 메뉴 문서를 쓸 때」 **2단계의 초벌 번역 산출물**
- 같은 절차 **3단계 3번 섹션(핵심 개념 및 설명)** — 원문 내용을 근거로 삼는 유일한 섹션

**나머지 섹션에는 적용하지 않는다.** 학습 목표, 예제 및 데모 설계, 연습 문제, 챕터 요약은 원문에 없는 창작물이며, 그게 정상이다. 아래 "원문에 없는 내용을 추가하지 않는다" 규칙을 이 섹션들에 적용하면 안 된다.

## 목표

3번 섹션은 학습자가 원문 대신 읽는 한국어 본문이다. 그래서 두 가지를 동시에 만족해야 한다.

- **정확성** — 원문의 기술적 사실, 조건, 강도를 왜곡하거나 흘리지 않는다.
- **가독성** — 원문을 옆에 두지 않고도 한 번 읽어 이해된다.

둘 중 하나만 만족하는 번역은 학습 자료로 쓸 수 없다. 정확하지만 읽히지 않는 문장은 학습자가 결국 원문을 다시 열게 만들고, 읽히지만 부정확한 문장은 잘못된 모델을 심는다. 아래 규칙은 「번역 원칙」이 정확성을, 「학습 자료로서의 품질」이 가독성을 담당한다.

## 번역 원칙

- 원문의 기술적 의미와 정보 범위를 정확하게 유지한다.
- 영어 문장 구조를 그대로 옮기지 않고 한국 개발자가 읽기 자연스러운 문장으로 재구성한다. 단, 과도한 의역으로 조건이나 범위가 흐려지지 않게 한다.
- 문장을 쉽게 풀어쓰되 기술적 정보나 조건은 생략하지 않는다.
- 원문에 없는 기술적 사실을 임의로 추가하지 않는다. 보충이 필요하면 아래 「추가 설명」 항목을 따른다.

### 강도를 바꾸지 않는다

원문의 **가능성·조건·권장·제한·경고 수준**을 그대로 유지한다. 이 문서군에서 가장 자주 발생하는 왜곡이다.

| 원문 | 옮길 때 | 쓰면 안 되는 표현 |
|---|---|---|
| `may`, `can` | ~할 수 있다 | ~한다, 항상 ~한다 |
| `we recommend`, `prefer` | ~하는 것을 권장한다, ~하는 편이 낫다 | ~해야 한다, 반드시 ~한다 |
| `must`, `required` | ~해야 한다 | ~하는 것이 좋다 |
| `in most cases`, `typically` | 대부분의 경우 ~한다 | 항상 ~한다 |
| `will not be`, `is not` | ~하지 않는다 | ~할 수도 있다 |

`항상`, `반드시`, `자동으로`, `절대`는 원문에 대응 표현(`always`, `must`, `automatically`, `never`)이 있을 때만 쓴다.

### 실행 맥락을 바꾸지 않는다

다음은 틀리면 학습자가 잘못된 모델을 갖게 되므로 원문 대조를 한 번 더 한다.

- **실행 시점**: build time / request time / revalidation 중 / 클라이언트 내비게이션 중
- **실행 환경**: 서버 / 브라우저 / 빌드 프로세스
- **처리 주체**: Next.js / React / 브라우저 / 사용자 코드

## 학습 자료로서의 품질

### 문장을 쪼갠다

영어는 관계절·분사구로 한 문장을 길게 잇지만, 한국어에서 같은 구조를 유지하면 수식 관계가 끊긴다. 한 문장이 세 줄을 넘거나 쉼표가 세 개 이상이면 두세 문장으로 나눈다. 정보는 그대로 유지하고 문장만 나눈다.

- 나쁨: 요청 시점에 결정되는 값을 읽는 함수에 수명을 부여하면 해당 결과가 `prefetch`에 포함될 수 있게 되어 클릭 전에 준비되므로 내비게이션이 빨라진다.
- 좋음: 요청 시점에 결정되는 값을 읽는 함수에도 수명을 부여할 수 있다. 그러면 그 결과가 `prefetch`에 포함되어 클릭 전에 준비된다. 결과적으로 내비게이션이 빨라진다.

### 명사를 나열하지 않고 관계를 드러낸다

영문 복합 명사구를 그대로 붙여쓰면 무엇이 무엇을 수식하는지 사라진다. 조사와 서술어로 관계를 드러낸다.

- 나쁨: 서버 컴포넌트 데이터 페칭 캐시 무효화 전략
- 좋음: `Server Component`에서 가져온 데이터의 캐시를 무효화하는 전략

### 수동태를 능동태로 바꾼다

`is cached`, `will be rendered` 같은 수동태는 한국어에서 주체를 흐린다. **원문에 주체가 드러나 있으면** 주어로 살린다. 원문이 주체를 밝히지 않았다면 추측해서 넣지 않고 `~된다`로 둔다.

- 원문에 주체 있음: "Next.js는 이 결과를 캐시한다"
- 원문에 주체 없음: "이 결과는 캐시된다"

### 지시어를 확정한다

`it`, `this`, `that`, `they`를 "이것", "그것"으로 옮기지 않는다. 문맥에서 가리키는 대상을 찾아 명시한다.

- 나쁨: 이것은 요청마다 다시 실행된다.
- 좋음: 이 함수는 요청마다 다시 실행된다.

### 관용 표현

원문에 반복적으로 나오는 표현은 아래 번역을 쓴다. 직역하면 어색해지는 것들이다.

| 원문 | 번역 |
|---|---|
| under the hood | 내부적으로는 |
| out of the box | 별도 설정 없이 |
| in this case | 이때 |
| that said | 다만 |
| this is because | ~때문이다 |
| note that | (문장을 `~라는 점에 유의한다`로 재구성) |
| keep in mind | (콜아웃으로 옮기거나 `~을 기억해두자`) |
| for example | 예를 들어 |
| as a result | 결과적으로 |
| by default | 기본적으로 / 기본값으로 |
| you can think of X as Y | X는 Y라고 보면 된다 |

### 학습 흐름은 재구성할 수 있다

원문의 문단 순서가 학습에 불리하면 3번 섹션에서 순서를 바꾸거나 묶어도 된다 — 개념 정의가 사용 예시보다 뒤에 나오는 경우가 대표적이다. 단, 재구성해도 원문의 H2/H3 항목 자체가 빠지면 안 된다([AGENTS.md](./AGENTS.md) 5단계 대조 절차).

### 코드 주석은 학습자 기준으로 쓴다

원문 주석이 짧아 맥락이 없으면(`// cache`) 그 코드가 왜 그렇게 쓰였는지 드러나게 옮긴다(`// 결과를 캐시해서 요청마다 다시 계산하지 않는다`). 주석은 원문 밖 정보 추가로 보지 않는다 — 본문이 이미 설명한 내용을 코드 옆에 붙이는 것이기 때문이다.

## 기술 용어

### 표기 원칙

1. **Next.js 고유 개념어·API·지시어는 원문 표기를 유지한다.** 대문자로 시작하는 개념명(`Server Component`), 함수·훅·지시어명(`revalidateTag`, `use cache`), 설정 키(`cacheComponents`)가 해당한다.
2. **일반 기술어로 한국어에 정착한 것은 한글로 쓴다.** 렌더링, 캐시, 라우트, 스트리밍 등.
3. 같은 용어는 문서 전체에서 한 가지 표기만 쓴다. 판단이 갈리면 아래 대응표를 따르고, 표에 없으면 **저장소에서 이미 다수로 쓰이는 표기**를 따른 뒤 표에 추가한다.
4. 한글만으로 의미가 불명확한 용어는 **파일 단위로 최초 등장 시** `한국어(영문)` 형태로 병기한다. 예: `고유한(intrinsic)`, `수명(lifetime)`. 학습자가 어느 챕터로든 바로 진입하므로 기준은 저장소 전체가 아니라 파일이다.

### 대응표

**원문 표기 유지**

| 용어 | 비고 |
|---|---|
| `revalidate` / `revalidation` | "재검증"으로 쓰지 않는다 |
| `prefetch` / `prefetching` | "프리페치/프리페칭"으로 쓰지 않는다 |
| `hydration` / `hydrate` | "하이드레이션"으로 쓰지 않는다 |
| `Server Component` / `Client Component` | "서버 컴포넌트"로 쓰지 않는다 |
| `Server Function` / `Server Action` | |
| `Route Handler` | |
| `prerender` / `prerendering` | "프리렌더"로 쓰지 않는다 |
| `mutation` / `mutate` | |
| `params` / `searchParams` / `payload` | 코드 식별자 |
| `App Shell` / `static shell` | |
| `proxy` | Next.js 16의 명칭. "미들웨어"로 쓰지 않는다 |
| `Suspense` / `streaming boundary` | |

**한글 표기**

| 용어 | 원문 |
|---|---|
| 렌더링 | rendering |
| 캐시 / 캐싱 | cache / caching |
| 라우트 / 라우팅 | route / routing |
| 스트리밍 | streaming |
| 다이나믹 | dynamic — Next.js 개념어를 수식할 때(`다이나믹 라우트`, `다이나믹 렌더링`, `다이나믹 params`). "동적"으로 쓰지 않는다 |
| 동적으로 | dynamically — 일반 부사일 때만(예: 콘텐츠를 동적으로 갱신한다) |
| 번들 / 번들링 | bundle / bundling |
| 빌드 | build |
| 요청 / 응답 | request / response |
| 컴포넌트 | component (단독 일반명사일 때만. 복합 개념어는 원문 유지) |

## 문체와 표기

- **리프 학습 문서 본문은 `~한다`체**로 쓴다. 실제 작성된 12개 문서가 모두 이 문체다.
- **카테고리 `README.md`(메뉴 페이지)는 `~합니다`체**를 유지한다.
- 아직 채우지 않은 스텁 문서는 `~합니다`체로 되어 있다. 그 챕터를 실제로 작성할 때 `~한다`체로 바꾼다.
- 규칙·ADR 문서(이 파일, `AGENTS.md`, `docs/adr/`)는 `~한다`체다.
- 원문의 `Good to know` 콜아웃은 `> **알아두면 좋은 점**:` 으로 옮긴다.

### 번역하지 않는 것

- 함수명, 변수명, 타입명, API명, 옵션·설정 키, 파일명, 디렉토리 경로, 패키지명, CLI 명령
- 코드블록 안의 코드와 **문자열 리터럴**
- 에러 메시지와 터미널·콘솔 출력 (원문 그대로 두고, 필요하면 바로 아래에 한글 설명을 덧붙인다)

### 번역하는 것

- 코드블록 안의 **주석**
- 표의 헤더와 셀 내용 (단, 셀이 코드 식별자면 유지)
- 헤딩 — 번역하되, 고유 개념어·API명은 위 대응표대로 원문을 유지한다. 결과적으로 `### Client Components`, `### 순차적 데이터 fetching`처럼 혼합 형태가 나오는 것은 정상이다.

## 링크·이미지·버전

- 원문 본문의 내부 링크(`/docs/app/...`)는 **대응하는 학습 문서의 상대 경로**로 바꾼다. 예: `[<Image>](../3-api-reference/3.2-components/image.md)`
- 대상 학습 문서가 아직 스텁이어도 상대 경로로 연결한다. 대응 문서가 아예 없으면 원문 링크를 그대로 둔다.
- 문서 상단의 「공식 출처」 링크는 항상 원문 URL을 쓴다.
- 이미지 캡션·alt 텍스트는 번역한다. 이미지 확인·배치 절차는 [AGENTS.md](./AGENTS.md) 2·4단계를 따른다.
- 원문이 특정 버전을 언급하면(`as of Next.js 15`) 그 서술을 그대로 옮긴다. [README.md](./README.md)의 학습 기준 버전과 어긋나면 임의로 고치지 않고 사용자에게 알린다.
- `canary`, `experimental`, `deprecated`, `unstable_` 표기는 누락 없이 옮긴다. 원문에 없으면 붙이지 않는다.

## 추가 설명

기본 번역에는 원문에 있는 정보만 쓴다. 보충하고 싶은 내용은 번역문에 섞지 않는다.

초벌 번역 단계에서는 `추가 설명` 영역을 따로 만들어 분리해둔다. 이 영역은 **중간 산물**이다. 최종 문서에서는 [AGENTS.md](./AGENTS.md)가 정한 6개 섹션 구조를 유지해야 하므로, 보충 내용은 다음 중 하나로 처리한다.

- 개념 이해에 필요하면 → 3번 섹션(핵심 개념 및 설명) 본문에 학습 문서의 서술로 녹인다
- 주의사항이면 → `> **알아두면 좋은 점**:` 콜아웃으로 옮긴다
- 학습 확인용이면 → 5번 섹션(연습 문제)으로 옮긴다
- 어디에도 안 맞으면 → 버린다

즉 `추가 설명`이 최종 문서의 7번째 섹션으로 남지는 않는다.

## 최종 검수

**정보 누락·구조 대조는 [AGENTS.md](./AGENTS.md) 5단계의 절차를 따른다** — 원문의 H2/H3 제목 목록, `Good to know` 콜아웃, 표의 행 개수를 하나씩 맞춰보는 그 절차다. 여기에 중복해서 적지 않는다.

### 정확성

1. 위 대응표의 용어 표기가 지켜졌는가? (특히 `revalidate` / `prefetch` / `hydration`)
2. 병기(`한국어(영문)`)가 파일 내 최초 등장 위치에 있는가?
3. `항상` / `반드시` / `자동으로` / `절대`가 원문 근거 없이 쓰이지 않았는가?
4. 원문의 `may` / `can` / `we recommend`가 단정으로 바뀌지 않았는가?
5. 실행 시점·실행 환경·처리 주체가 원문과 같은가?
6. 코드블록 내 문자열 리터럴과 에러 메시지가 번역되지 않고 남아 있는가?
7. 원문 내부 링크가 학습 문서 상대 경로로 바뀌었는가?

### 가독성

원문을 덮어두고 번역문만 다시 읽으면서 확인한다. 원문을 보면서 검수하면 뜻이 통하는 것처럼 느껴져서 걸러지지 않는다.

8. 한 번 읽어서 이해되지 않는 문장이 있는가? 있으면 쪼갠다.
9. 세 줄을 넘는 문장이나 쉼표가 세 개 이상인 문장이 남아 있는가?
10. 수식 관계가 모호한 명사 나열이 있는가?
11. "이것" / "그것"으로 남은 지시어가 있는가?
12. 문체가 `~한다`체로 통일되었는가? (메뉴 페이지는 `~합니다`체)
13. 코드 주석만 읽어도 그 줄이 왜 필요한지 짐작되는가?
