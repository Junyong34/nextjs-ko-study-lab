# nextjs-learning 작업 규칙

Next.js App Router 공식 문서(nextjs.org/docs/app)를 한국어 학습 커리큘럼으로 재구성하는 프로젝트다. 코드보다 문서(md)가 먼저다.

## 시작할 때 먼저 읽을 것

- [README.md](./README.md) — 전체 카테고리 목차, 학습 흐름, 문서 작성 원칙
- [CONTEXT.md](./CONTEXT.md) — 용어집 (학습 문서 / 메뉴 페이지 / 학습 카테고리 / 데모 등)
- [PROGRESS.md](./PROGRESS.md) — 전체 메뉴의 순번·진행 상태. **다음에 뭘 쓸지는 항상 여기서 정한다.**
- [docs/adr/](./docs/adr/) — 구조·순서 결정 기록 (0001 계층 미러링, 0002 학습 순서 재배열)

## 새 메뉴 문서를 쓸 때

1. `PROGRESS.md`에서 md 상태가 "미작성"이거나 "초안"인 항목 중 순번이 가장 앞선 것을 고른다.
2. 그 항목의 공식 링크를 열어 원문을 확인하고 초벌 번역한다. 이 번역문은 중간 산물일 뿐이며 최종 파일에는 남기지 않는다. 이미지 유무는 브라우저(chrome-devtools)로 페이지를 직접 열어 `document.querySelectorAll('img')`로 확인한다 — 텍스트/마크다운 추출 도구(wigolo fetch 등)가 돌려주는 `images` 필드만으로는 판단하지 않는다. 공식 문서는 이미지를 라이트/다크 테마 쌍으로 렌더링하는데, 이 구조가 로고·아이콘 같은 장식 이미지와 똑같아서 추출 도구가 콘텐츠 스크린샷까지 함께 걸러내는 경우가 있었다(Installation 챕터에서 실제로 놓친 사례).
   - **이미지가 2개 이상이면 배치를 추정하지 않는다.** 각 이미지의 바로 앞 헤딩(prevHeading)을 DOM에서 직접 읽어(`img.closest('figure')` 등에서 `previousElementSibling`을 따라 올라가며 가장 가까운 `H1~H6` 찾기) "헤딩 → 이미지" 매핑표를 먼저 만들고, 그 매핑표대로 캡쳐·배치한다. 번역된 텍스트 순서만 보고 "이 헤딩엔 이 이미지가 맞겠다"고 짐작하면 순서가 한 칸씩 밀리는 식으로 틀릴 수 있다(Project Structure 챕터에서 이미지 14~17번이 실제로 이렇게 밀려서 배치된 사례 — 다운로드한 이미지를 Read로 직접 열어 시각적으로도 재확인해서 잡았다).
3. 번역을 바탕으로 아래 6개 섹션을 모두 갖춘 문서를 한 번에 작성한다. 파일명·순번·링크는 해당 카테고리(또는 하위그룹) `README.md`에 이미 적힌 것을 그대로 쓴다:
   1. 공식 출처(원문 링크) / 상위 메뉴 / 전체 목차 링크
   2. 학습 목표
   3. 핵심 개념 및 설명 — 번역문이 아니라 학습 목표·핵심 개념에 맞게 재구성한 한글 본문. 코드는 md 코드블록으로 작성하고, 코드 식별자는 원문 그대로 유지한다.
   4. 예제 및 데모 설계 (Phase 1에서는 "구현 예정"으로만 남겨도 됨 — 아래 Phase Gate 참고)
   5. 연습 문제 1~3개 — 객관식(단일 선택 또는 복수 선택)만 사용한다. `<details><summary>정답 보기</summary>` 안에 정답과 한 줄 해설을 적어 접어둔다.
   6. 챕터 요약 — 5줄 내외 불릿 포인트.
4. 2번에서 확인한 이미지가 있으면 공식 문서 페이지를 직접 열어 캡쳐하고, `<카테고리>/assets/<slug>-NN.png`로 저장해 원문과 같은 위치에 참조한다. 캡쳐가 잘못됐거나 대상이 애매하면 사용자에게 확인받거나 대체 이미지 경로를 받는다.
5. **초안을 다 쓴 뒤, 제시하기 전에 원문과 나란히 대조해서 빠진 게 없는지 검증한다.** 원문의 H2/H3 제목 목록, "Good to know" 콜아웃, 표의 행 개수를 초안과 하나씩 맞춰본다. 요약·재구성하다가 소제목 하나가 통째로 빠지거나(예: Project Structure의 "Component hierarchy" 섹션), 콜아웃 안의 항목 일부만 옮겨지는(3개 중 1개만) 실수가 실제로 있었다. 표 안의 여러 행을 하나로 합칠 때도 원문에서 각 행의 설명이 서로 다르면(예: `.env`/`.env.local`/`.env.production`) 합치지 말고 그대로 유지한다.
   - **이미지 검증은 "지금 문서에 몇 개 있는지"가 아니라 "그 슬러그로 `assets/`에 몇 개가 다운로드돼 있는지"를 기준으로 한다.** 이미 완료된 챕터를 나중에 다시 검증할 때, 문서에 이미지가 하나도 없다고 해서 "원래 이미지가 없었을 것"이라고 넘겨짚지 않는다. `assets/<slug>-*.png` 파일이 실제로 몇 개 있는지 먼저 세어보고, 그 개수와 문서에서 참조하는 개수를 맞춰본다. 다른 항목을 검증하다가 "번역 초안을 쓸 때 이미지를 캡쳐해놓고 실제로는 한 장도 문서에 넣지 않은" 챕터를 놓친 사례가 있었다(Layouts and Pages — 5개를 캡쳐해놓고 0개를 썼는데, 검증할 때도 문서만 보고 "이미지 없는 챕터"로 잘못 분류함).
6. 완성한 전체 초안을 한 번에 제시한다. 사용자가 직접 읽고 검토하며 수정·보강한 내용을 반영한다.
7. 위 6개 섹션이 실제 내용으로 채워졌으면 `PROGRESS.md`의 md 상태를 "완료"로, 아직 얕으면 "초안"으로 갱신한다. 한 번에 완벽해야 하는 건 아니다 — 나중에 다시 보강해도 된다.

완료 기준: 6개 섹션(출처/상위메뉴/전체목차, 학습 목표, 핵심 개념 및 설명, 예제 및 데모 설계, 연습 문제, 챕터 요약)이 모두 채워졌고 `PROGRESS.md`의 해당 행이 갱신되어 있다.

## 순번 규칙

카테고리·하위그룹은 실제 디렉토리 뎁스를 반영한 트리 번호(`1.1`, `3.1.1`)를 쓴다. 순서를 새로 정하거나 바꿀 때는 [ADR 0002](./docs/adr/0002-reorder-learning-sequence.md)의 원칙(의존성 있는 항목은 재배열 / 이미 순차적인 항목은 유지 / 독립적 참조 목록은 그룹까지만 번호)을 따르고, `PROGRESS.md`와 해당 `README.md`를 함께 갱신한다.

카테고리·하위그룹 **폴더명**에는 번호를 접두어로 붙인다 (`1-getting-started`, `2-guides/2.44-testing`, `3-api-reference/3.1-file-conventions`). 개별 리프 `.md` **파일명**에는 붙이지 않는다 — 수가 많아 링크 부담이 크기 때문이다. 새 하위그룹 폴더를 만들 때도 이 규칙을 따르고, 상위 `README.md`의 링크를 함께 갱신한다.

## 버전

학습 기준 Next.js 버전은 [README.md의 기준 출처](./README.md)에 고정되어 있다 (작성 시점: 16.3.0). 새 세션에서 이 프로젝트 작업을 시작하면, 먼저 `npm view next version`(또는 nextjs.org/blog)으로 실제 최신 버전과 비교한다. 메이저·마이너가 올라가 있으면 사용자에게 알리고, README.md의 버전 값을 갱신한 뒤 영향받을 만한 "완료" 문서를 재검토 대상으로 표시한다.

## Phase Gate

지금은 **Phase 1: 문서화**다. 데모 앱이나 실행 코드는 만들지 않는다. `PROGRESS.md`의 항목이 대부분 "완료"가 된 뒤에야 Phase 2(로컬 Next.js 데모 앱: App Router + TypeScript + Tailwind)로 넘어간다. Phase 2 앱은 저장소 루트의 형제 폴더 [`nextjs-app/`](../nextjs-app/README.md)에 배치하기로 미리 정했다(루트 [README.md](../README.md) 참고). 실제 스캐폴딩과 세부 라우팅 구조는 Phase 2 착수 시점에 확정한다.
