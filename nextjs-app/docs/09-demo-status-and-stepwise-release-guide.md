# 09. 실습 예제 상태(Status) 관리 및 단계별 순차 오픈 가이드

Next.js 학습 랩(`nextjs-app`)의 실습 예제 241개를 안전하게 운영하고, 직접 검증 완료한 예제만 단계별로 순차 오픈하기 위한 상태 관리 규칙과 화면 노출 기준을 설명합니다.

---

## 1. 도입 배경 및 목적

- **품질 및 검증 리스크 방어**: 241개의 모든 데모를 한 번에 오픈할 경우 미검증된 동작이나 버그가 사용자에게 노출될 위험이 있습니다.
- **단계별 점진적 릴리즈**: 작업자가 직접 브라우저 및 배포 환경에서 기능과 시나리오를 확인한 챕터(예: "시작하기")만 우선 정식 공개하고, 나머지는 안전하게 "준비 중"으로 격리합니다.
- **일관된 UX 제공**: 사이드바 목차, 데모 색인 카드, 상세 실행 화면, 홈 화면 책장, 개인 학습 현황 등 사이트 전반에서 준비 중 상태를 일관되게 방어합니다.

---

## 2. 데모 상태(Status) 체계 및 단일 원본(SSOT)

데모의 상태는 **`nextjs-app/packages/demos/demos.yaml`**이 유일한 원본(SSOT)입니다.

### 📌 상태 정의

| 상태 값 | 명칭 | 의미 및 용도 |
| :--- | :--- | :--- |
| **`done`** | **공개 완료** | 직접 동작과 시나리오를 확인하여 정식 공개된 상태 |
| **`stub`** | **준비 중 (기본)** | URL과 기본 골격이 생성되었으나 아직 직접 검증 전인 상태 |
| **`wip`** | **제작 / 작업 중** | 데모 코드 작성 및 수정 작업이 진행 중인 상태 |

> `demos-manifest.json`은 `demos.yaml`을 기반으로 자동 빌드되는 파일이므로 직접 편집하지 않습니다.

## 3. 화면 영역별 노출 및 방어 로직

```
┌────────────────────────────────────────────────────────────────────────┐
│                              화면별 노출 규칙                          │
├────────────────────┬─────────────────────┬─────────────────────────────┤
│ 화면 / 영역        │ `done` (검증 완료)   │ `stub` / `wip` (준비 중)    │
├────────────────────┼─────────────────────┼─────────────────────────────┤
│ 1. 사이드바 (데모) │ 초록색 [예제 (N)]   │ 회색 [준비 중]              │
│ 2. 사이드바 (문서) │ 우측 초록 재생(▶)   │ 재생 아이콘 숨김            │
│ 3. 실습 색인(/demo)│ 통계 집계 / 정상카드│ [준비 중] 배지 부착         │
│ 4. 데모 뷰어 진입  │ 인터랙티브 데모 실행│ [준비 중입니다] 안내창 방어 │
│ 5. 학습현황 진도표 │ 체크리스트에 포함   │ 체크리스트에서 자동 제외    │
│ 6. 홈 화면 책장    │ [예제 25개] 책 노출 │ 예제 책 숨김 (오작동 방지)  │
│ 7. 문서 하단 카드  │ 정상 열람           │ [준비 중] 태그 표시         │
└────────────────────┴─────────────────────┴─────────────────────────────┘
```

### ① 좌측 사이드바 목차 (`DocTree`)
- **실습 예제 모드 (`/demo/...`)**:
  - 해당 문서에 `done` 예제가 1개 이상 있음: **초록색 `[예제]` (또는 `[예제 (N)]`)** 뱃지 활성화
  - 해당 문서의 모든 예제가 `stub` 상태임: **회색 `[준비 중]`** 뱃지 표시
- **학습 문서 모드 (`/getting-started/...`, `/guides/...`)**:
  - `done` 예제가 있는 문서에만 우측 **초록색 재생(▶) 아이콘** 표시

### ② 실습 예제 색인 페이지 (`/demo`)
- **상단 통계 카드 (`DemoIndexStats`)**: `구현 완료` 수치에 `done` 상태인 예제만 집계 (예: 241개 중 25개 완료).
- **개별 예제 카드 (`DemoIndexCard`)**: `stub` 상태 예제는 카드 우측 상단에 **`준비 중`** 뱃지 부착.

### ③ 데모 상세 및 문서별 데모 허브 (`/demo/[문서경로]`)
- **`done` 예제가 있는 경우**: 정상적으로 데모 카드 및 인터랙티브 뷰어(iframe) 실행 가능.
- **`stub` 예제만 있는 경우**: 미완성 데모 실행을 차단하고 **`DemoEmptyState` ("이 주제의 실습 예제가 준비 중입니다")** 전용 안내 화면 노출 (학습 문서 바로가기 버튼 제공).

### ④ 개인 학습 현황 대시보드 (`/study-progress`)
- 학습자가 완료 체크를 진행할 수 있는 실습 목록에 **`done` 상태 예제만 등록**되어 진도율 왜곡 방지.

### ⑤ 메인 홈 화면 (`/`)
- **로드맵 북셸프 (`RoadmapBookshelf`)**: `done` 예제가 존재하는 챕터(예: Step 01 시작하기)에만 실습 예제 책과 카운트 뱃지 노출.
- **주요 실습 예제 (`FeaturedDemosSection`)**: 검증 완료된 `done` 예제들로만 추천 구성.

## 4. 운영 작업 절차 (단계별 추가 오픈 방법)

새로운 챕터(예: 가이드의 Server Actions 등)를 직접 검증하고 사용자에게 오픈할 때는 다음 절차를 따릅니다.

### Step 1. 로컬 환경에서 데모 직접 확인
개발 서버를 실행하고 대상 데모의 4단 레이아웃과 동작을 검증합니다.
```bash
cd nextjs-app
pnpm dev
```
> 브라우저에서 직접 존 경로(예: `http://localhost:3000/zone/baseline/server-actions/basic`)에 접속하여 정상 동작 확인

### Step 2. `demos.yaml` 상태 변경
`nextjs-app/packages/demos/demos.yaml` 파일에서 검증 완료한 항목의 `status`를 `done`으로 변경합니다.
```yaml
- url: server-actions/basic
  title: "Server Actions 기본 폼 처리 및 상태 변경"
  doc: 2-guides/server-actions.md
  zone: baseline
  status: done   # stub -> done 으로 변경
```

### Step 3. 매니페스트 동기화 빌드
```bash
pnpm --filter @study/demos build
```
빌드가 완료되면 `demos-manifest.json`이 자동으로 갱신되며, 사이트의 사이드바 메뉴, 예제 색인, 상세 실행 화면이 즉시 정식 오픈 상태로 전환됩니다.

### Step 4. 변경 사항 확인 및 커밋
```bash
git add nextjs-app/packages/demos/
git commit -m "[$GIT_BRANCH_NAME][feat]: {오픈한 주제명} 실습 예제 정식 오픈"
```
