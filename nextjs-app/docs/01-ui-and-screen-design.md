# 01. 화면 구성과 UI 설계

2026-09-05 소스 기준의 화면 구성과 기존 설계 중 남은 항목을 구분한다. 시스템 경계는 [ARCHITECTURE](../ARCHITECTURE.md), 디자인 방향은 [DESIGN](../../DESIGN.md), 공개 상태 규칙은 [09](./09-demo-status-and-stepwise-release-guide.md)가 담당한다.

## 1. 화면 골격

`AppFrame`은 홈과 학습 기록 화면에서만 사이드바를 숨긴다. 그 외 문서와 데모 화면에는 `DocTree`가 있으며 모바일에서는 서랍으로 제공한다.

| 화면 | URL | 주요 구성 |
|---|---|---|
| 홈 | `/` | 히어로·책장·추천 카드·학습 기록 위젯 |
| 카테고리·학습 문서 | `/{문서 slug}` | 문서 트리·Markdown 본문·문서 목차 |
| 예제 색인 | `/demo` | 예제 트리·검색·카테고리 필터·페이지 이동 |
| 문서별 예제 허브 | `/demo/{문서 slug}` | 연결 예제 목록 또는 준비 중 안내 |
| 예제 독립 열람 | `/demo/{데모 url}` | 셸 헤더·학습 기록·iframe·관련 예제 |
| 학습 기록 | `/study-progress` | 문서/데모 탭·필터·완료 표시 |

실제 공개·미공개 분기는 09번의 화면별 표를 따른다. 이 문서의 소스 대조를 브라우저 접근성 검증으로 간주하지 않는다.

## 2. 랜딩 `/`

### 2-1. 구성

`apps/shell/src/app/page.tsx`는 `RoadmapHero`, `RoadmapBookshelf`, `FeaturedDemosSection`, `LearningProgressWidget`을 조립한다. Next16HighlightsSection은 호출이 주석 처리돼 있다.

문서 합계는 문서 매니페스트, 데모 합계는 `getDemos()`의 YAML 조회에서 전달하지만 히어로의 프레임워크 버전 배지는 코드 문자열이다. 등록 데모 수를 공개·검증 완료 수로 해석하지 않는다. 책장의 예제 개수는 카테고리별 `done`을 세고, 추천 카드는 컴포넌트의 고정 목록이다.

### 2-2. 히어로의 대표 예제 — 과거 설계

초기 설계는 `featured: true` 데모 하나를 iframe으로 표시하려 했다. 현재 홈은 iframe을 렌더링하지 않으며 매니페스트 스키마에도 `featured` 필드가 없다. 이 설계를 현행 구현 계약으로 사용하지 않는다.

### 2-3. 대표 예제가 실패했을 때

초기 대표 iframe의 고정 높이·정적 폴백은 현재 홈에 적용되지 않는 과거 설계다. 홈 추천 링크의 상태 처리 한계는 09번, 독립 열람 iframe은 5-2를 참조한다.

### 2-4. 재검토 조건

향후 대표 iframe을 다시 도입한다면 대상 선정·공개 상태·로딩 실패·높이·성능을 별도 설계하고 검증한다. 이번 문서 정비에서는 도입하지 않는다.

## 3. 학습 문서

### 3-1. 본문

`MarkdownRenderer`가 원본 Markdown과 코드 블록을 렌더링한다. 학습 문서의 작성 형식은 `nextjs-docs/AGENTS.md`의 책임이며 이 문서에서 재정의하지 않는다.

### 3-2. 예제는 심지 않고 링크로 넘긴다

본문의 `demo` 코드펜스는 `DemoLinkCard`로 변환한다. 학습자 이동은 `/demo/{url}`이며 본문에 실행 iframe을 두지 않는다. [ADR 0006](./adr/0006-shadcn-ui-as-ui-foundation.md)

### 3-3. 예제 링크가 나타나는 두 자리

본문 지시자는 링크 위치를 정하고, 문서 하단 `DocDemoList`는 데모 목록의 `doc` 필드로 연결된 항목을 표시한다. 본문 링크에는 상태 배지가 없고 하단 목록에는 준비 중 배지가 있다. 목록 존재와 실행 가능 여부는 다르다.

### 3-4. 코드펜스에 붙는 lint

`pnpm --filter @study/demos lint`가 지시자와 목록·문서·라우트 정합성을 검사한다. 명령은 저장소 루트에서 실행한다. 색상 토큰이나 브라우저 동작을 검증하는 명령은 아니다.

### 3-5. 우측 페이지 목차

문서의 heading 정보를 바탕으로 페이지 내 이동을 제공한다. 화면별 표시와 활성 위치·스크롤 처리는 문서 라우트 및 `packages/ui/src/nav/`에서 확인한다.

### 3-6. 한글 본문 조판

코드 식별자는 보존하며 긴 제목·코드·표가 좁은 화면에서 잘리는지 별도 브라우저 확인이 필요하다. 조판 방향은 DESIGN을 따른다.

## 4. 카테고리 홈

비어 있지 않은 문서 slug는 catch-all 문서 라우트가 담당한다. `/`는 전용 홈 컴포넌트이므로 루트 학습 README의 단순 렌더링과 구분한다.

## 5. 예제 색인과 독립 열람

### 5-1. 색인

`demo-index.ts`와 `demo-index-items.ts`가 검색·정렬과 클라이언트 전달 데이터를 구성한다.

- 제목·학습자 URL·관련 문서명을 검색하며 일치 순위와 원본 순서로 정렬한다.
- `q`, `category`, `page` 쿼리로 상태를 표현하고 페이지당 24개를 제공한다.
- 카드 링크와 관련 문서 링크는 별도 탐색 대상이다.
- `study_demo_list_context` sessionStorage로 목록 복귀 위치를 관리한다. 복원·만료·쿼리 불일치 처리는 `useDemoListRestoration`과 `demo-storage`가 담당한다.
- 전체 등록 목록과 공개 개수는 구분하며 준비 중 카드도 표시한다.

### 5-2. 독립 열람

`DemoViewer`가 셸 UI와 `DemoIframe`을 조립한다. iframe은 `/zone/{zone}/{url}`을 요청하고 셸이 zone으로 rewrite한다. 높이 메시지 흐름은 ARCHITECTURE를 참조한다. 관련 예제와 `?run=` 선택의 현재 제한은 09번에 기록한다.

## 6. 헤더와 검색

### 6-1. 헤더

`HeaderBrand`와 `HeaderNav`가 학습 문서(`/getting-started`), 예제(`/demo`), 공식 문서, GitHub 링크를 제공한다. sticky 헤더이며 현재 전역 검색 팔레트와 테마 토글은 없다.

### 6-2. 화면 라벨과 도메인 용어는 다르다

화면에는 `예제`, 코드·URL·설계 문서에는 `데모`를 쓴다. [CONTEXT](../CONTEXT.md)의 용어를 따른다.

### 6-3. 검색 — 현재 동작과 미구현 설계

현재 검색은 `DocTreeSearch`의 목차 필터와 `/demo`의 검색·카테고리 필터다. 전역 `⌘K` 팔레트, 문서/예제 그룹 검색, 최근 본 문서, 형태소·오타 검색은 구현 완료 기능으로 안내하지 않는다. 도입하려면 별도 계획이 필요하다.

## 7. UI 기반

### 7-1. 기존 결정과 적용 범위

[ADR 0006](./adr/0006-shadcn-ui-as-ui-foundation.md)은 shadcn/ui 기반과 문서 프레임워크 배제를 결정했다. 현재 소스에는 자체 프리미티브와 Tailwind 클래스가 있으며 ADR의 모든 도입 항목이 구현됐다고 가정하지 않는다.

### 7-4. 패키지 배치

셸 UI는 `@study/ui`, 데모 UI는 `@study/demo-kit`, Markdown 렌더링은 `@study/docs-render`가 담당한다. 세 패키지의 역할과 상세 코드는 [02](./02-codebase-deep-dive-guide.md)를 참조한다.

## 8. 디자인 토큰

### 8-1. 색

DESIGN과 기존 ADR은 디자인 방향이다. 현재 적용 값은 셸 `globals.css`, 패키지 `styles.ts`, 개별 컴포넌트의 클래스에서 확인한다. 모든 색이 중앙 토큰으로 통합됐다고 설명하지 않는다.

### 8-2. 다크 모드

컴포넌트에는 `dark:` 변형이 있지만 현재 헤더에 테마 토글은 없다. `study_theme`는 기존 작업 규칙의 예약 이름이며 저장·복원 기능의 구현 증거가 아니다.

## 9. 기존 결정과의 관계

ADR의 결정 이유는 보존하고 구현과 다른 항목은 위에서 구분했다. 홈 iframe·전역 검색·테마 토글을 이번 작업에서 새로 구현하지 않는다.

## 10. 검증 기준

문서·색인·허브·직접 실행·학습 기록의 실제 화면, 키보드 이동, 좁은 화면, iframe 로딩 실패를 각각 확인해야 한다. 이번 최신화는 코드 대조이며 이 시나리오의 새 브라우저 검증 결과를 추가하지 않았다.
