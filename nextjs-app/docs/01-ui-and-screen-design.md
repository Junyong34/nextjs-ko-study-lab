03이 **주소**를 정했다면 이 문서는 그 주소에서 **무엇이 그려지는가**를 정합니다. 화면 골격, 각 페이지의 구성, 헤더와 검색, UI 기반 라이브러리, 디자인 토큰까지가 범위입니다.

## 1. 화면 골격 — 페이지 타입은 5종

03. 3-1의 URL 계약이 다섯 종류의 페이지를 만들어냈습니다. **전 페이지 공통은 상단 바 하나뿐**이고, 좌측·우측은 타입마다 켜고 끕니다.

| # | 페이지 타입 | URL | 상단 | 좌측 | 우측 | 본문 폭 |
|:---:|---|---|:---:|---|---|---|
| ① | 사이트 랜딩 | `/` | 공통 | — | — | 넓게 (1200px) |
| ② | 카테고리 홈 | `/getting-started` | 공통 | 문서 트리 | — | 본문폭 |
| ③ | 학습 문서 | `/getting-started/caching` | 공통 | 문서 트리 | 페이지 목차 | 본문폭 (740px) |
| ④ | 예제 색인 | `/demo` | 공통 | — | — | 넓게 |
| ⑤ | 예제 독립 열람 | `/demo/caching/use-cache-basic` | 공통 | — | — | 본문폭 |

```
① 랜딩                    ③ 학습 문서                 ⑤ 예제 독립 열람
┌──────────────────┐     ┌──────────────────┐        ┌──────────────────┐
│ 상단 바           │     │ 상단 바           │        │ 상단 바           │
├──────────────────┤     ├────┬────────┬────┤        ├──────────────────┤
│                  │     │ 문 │        │ 페 │        │   chrome (셸)    │

│                  │     │ 트 │        │ 지 │        │  iframe (데모앱)  │
├──────────────────┤     │ 리 │        │ 목 │        ├──────────────────┤
│  카테고리 · 예제  │     │    │        │ 차 │        │   관련 예제       │
└──────────────────┘     └────┴────────┴────┘        └──────────────────┘

**②는 ③의 변형입니다.** 좌측이 같고 우측만 끕니다. 별도 레이아웃을 만들지 않고 같은 레이아웃에서 우측 슬롯을 비웁니다.

### 왜 ①·④·⑤에 좌측 트리가 없는가

랜딩의 질문은 "어디부터 읽지"입니다. 264편짜리 트리를 첫 화면에 펼치면 그 질문에 답하는 게 아니라 **질문을 더 어렵게 만듭니다.** ④·⑤는 예제에 집중시키는 화면이고, ⑤의 복귀 경로는 chrome의 "이 예제의 문서로" 링크입니다.

### 2-2. 히어로의 대표 예제 — 이 사이트의 유일한 예외

문서 본문에는 예제를 심지 않습니다(3-2). **랜딩만 예외로 iframe을 하나 둡니다.**

예외를 두는 이유는 첫인상입니다. "동작하는 예제가 있다"를 글자로만 주장하면 흔한 문서 사이트와 구별되지 않고, 그 증거가 스크롤 아래에 있으면 대부분 못 봅니다.

| 항목 | 규칙 |
|---|---|
| 대상 지정 | `demos.yaml`의 `featured: true`. **전체에서 최대 1개**, `status: done`이어야 함 |
| 높이 | **고정.** 높이 브릿지(`postMessage`)를 쓰지 않습니다 |
| 로딩 | `loading="eager"` — 화면 최상단이라 lazy는 부적절 |
| 실패 시 | 정적 폴백 패널로 대체 (2-3) |
| lint | `featured: true`가 2개 이상이거나 `status != done`이면 실패 |

높이를 고정하는 이유는 CLS입니다. 랜딩 최상단에서 iframe이 늘어나면 헤드라인이 밀립니다. 대표 예제는 **높이가 변하지 않는 것으로만** 고릅니다.

### 2-3. 대표 예제가 실패했을 때

랜딩이 데모 zone의 배포에 의존하게 되므로 03. 6-7의 배포 시점 어긋남이 **첫 화면**에 나타납니다. 그대로 두면 사이트 첫인상이 빈 사각형입니다.

셸이 iframe 뒤에 정적 폴백을 깔아둡니다. iframe이 로드에 성공하면 덮이고, 실패하면 그대로 보입니다.

```
┌──────────────────────────────┐
│ 기대   새로고침해도 값이 유지됨 │
│ 실제   지금은 확인할 수 없습니다│
│                              │
│ 예제 서버를 준비 중입니다.      │
│ 예제 전체 보기 →              │
└──────────────────────────────┘
```

**폴백은 셸이 그리므로 절대 실패하지 않습니다.** 실제 값처럼 보이는 가짜 타임스탬프를 그리지 않습니다 — 틀린 것을 보여주느니 확인할 수 없다고 말합니다(03. 4-8의 원칙).

### 2-4. 재검토 조건

이 예외는 **구현 중에 철회될 수 있습니다.** 아래 중 하나라도 발생하면 히어로 우측을 커리큘럼 진도판이나 여백으로 교체하고 이 절을 갱신합니다.

- 랜딩 LCP가 iframe 때문에 목표를 넘음
- 폴백이 실제로 보이는 일이 반복됨 (데모 zone 배포가 자주 늦음)
- 고정 높이에 맞는 대표 예제를 고르기 어려움

## 3. 학습 문서 `/{카테고리}/{하위그룹}/{파일명}`

264편이 여기 그려집니다. 사이트의 본체입니다.

### 3-1. 본문 — md의 6개 섹션이 그대로 화면 구조

[`nextjs-docs/AGENTS.md`](../../nextjs-docs/AGENTS.md)가 모든 학습 문서에 6개 섹션을 강제합니다. 이 제약이 화면 설계를 대부분 끝내줍니다.

| md 섹션 | 화면 처리 |
|---|---|
| 1. 공식 출처 / 상위 메뉴 / 전체 목차 | **브레드크럼 + 원문 링크**로 변환. 본문에 링크 3줄로 남기지 않습니다 |
| 2. 학습 목표 | 본문 |
| 3. 핵심 개념 및 설명 | 본문 + 코드블록 + 이미지 |
| 4. 예제 및 데모 설계 | 본문. `데모 가능 여부` 판정 라인은 **화면에 표시하지 않습니다** (작성자용) |
| 5. 연습 문제 | md의 `<details>`를 **그대로 살려** 스타일만 입힙니다. 정답은 접힌 채 시작 |
| 6. 챕터 요약 | 본문 |

본문 아래에 셸이 두 블록을 덧붙입니다.

- **이 문서의 예제** — `demos.yaml`의 `doc` 필드로 조인 (03. 4-4)
- **이전 / 다음 문서** — 카테고리 `README.md`의 `## 학습 순서`가 순서의 원본

### 3-2. 예제는 심지 않고 링크로 넘긴다

**문서 본문에 iframe을 두지 않습니다.** 예제는 항상 `/demo/…`로 이동해서 봅니다.

이 결정이 없애는 것들입니다.

| 사라짐 | 있던 곳 |
|---|---|
| `demo` 코드펜스의 `mode` · `height` 필드 | 03. 4-2 |
| 문서 페이지에서의 iframe 높이 브릿지 | 03. 4-6 |
| 데모 zone 빌드 실패가 **문서 페이지**를 오염시키는 문제 | 03. 6-7 |
| 문서 페이지의 클라이언트 JS 대부분 | — |

높이 브릿지 자체는 ⑤ 독립 열람이 여전히 iframe이라 살아남습니다. **쓰이는 곳이 한 군데로 줄어들 뿐입니다.**

### 3-3. 예제 링크가 나타나는 두 자리

```markdown
`use cache`를 붙인 함수는 결과가 캐시되어 다음 요청에서 재사용된다.

```demo
path: caching/use-cache-basic
caption: 새로고침해도 타임스탬프가 그대로인지 확인
```

캐시 항목의 수명은 `cacheLife`로 정한다.
```

| 필드 | 필수 | 의미 |
|---|:---:|---|
| `path` | ✅ | `demos.yaml`의 `url`과 같은 값 |
| `caption` | | 무엇을 관찰하라고 지시하는 한 줄. 카드 부제로 그려짐 |

렌더 결과는 iframe이 아니라 **링크 카드**입니다.

```
┌───────────────────────────────────────────────┐
│ ▶  예제 — use cache 기본 동작          열기 → │
│    새로고침해도 타임스탬프가 그대로인지 확인      │
└───────────────────────────────────────────────┘
```

그리고 문서 하단에 **"이 문서의 예제"** 목록이 항상 붙습니다. 코드펜스가 없어도 나타납니다.

**중복은 허용합니다.** 본문 카드로 이미 나온 예제도 하단 목록에 그대로 나옵니다. 하단 목록이 *그 문서의 완전한 예제 목록*이라는 성질이, 중복을 피하는 것보다 중요합니다. 본문 카드는 그중 일부로 가는 지름길입니다.

### 3-4. 코드펜스에 붙는 lint

| 검사 | 어기면 |
|---|---|
| `path`가 `demos.yaml`에 존재하는가 | 링크가 404로 감 |
| 그 예제의 `doc`이 **이 문서**를 가리키는가 | 다른 문서의 예제를 심어 하단 목록과 어긋남 |
| `mode` · `height` · `zone` 필드가 남아 있지 않은가 | 옛 형식이 조용히 무시됨 |

`status`가 `done`이 아닌 예제를 심으면 **렌더에서 조용히 생략**합니다. lint 실패로 만들지 않습니다 — `status`가 노출을 제어하는 유일한 스위치라는 규칙(03. 4-1)을 그대로 따릅니다.

### 3-5. 우측 페이지 목차

```
이 페이지
  학습 목표
  핵심 개념 및 설명     ← 스크롤 위치 강조
  예제 및 데모 설계
  연습 문제
  챕터 요약
  ───────────
  이 문서의 예제
  GitHub 원문
```

**모든 문서가 같은 5~6개 항목을 갖습니다.** 문서마다 목차가 들쭉날쭉한 보통의 문서 사이트와 다릅니다. md 구조가 강제돼 있어서 생기는 이득입니다.

H3 이하는 목차에 넣지 않습니다. 3번 섹션(핵심 개념)에만 H3가 많은데, 그것까지 넣으면 목차가 한 섹션에 쏠려 균형이 깨집니다.

하단의 "이 문서의 예제"는 목차 항목이자 **긴 문서에서 예제를 발견하는 경로**입니다. 3-2에서 본문 임베드를 없앤 대가를 여기서 갚습니다.

### 3-6. 한글 본문 조판

한국어 문서라서 기본값으로 두면 안 되는 것들입니다.

| 속성 | 값 | 이유 |
|---|---|---|
| `word-break` | `keep-all` | 기본값은 한글을 단어 중간에서 자릅니다 |
| `overflow-wrap` | `break-word` | `keep-all` 때문에 긴 코드 식별자가 넘치는 것을 막습니다 |
| `line-height` | `1.8` (본문) | 한글은 라틴 문자보다 넓은 행간이 필요합니다 |
| 본문 폭 | `740px` | 한글 기준 한 줄 45~50자 |

## 4. 카테고리 홈 `/{카테고리}`

`README.md`가 그대로 이 페이지가 됩니다 (03. 3-1의 URL 규칙).

| 블록 | 출처 |
|---|---|
| 카테고리 제목 + 설명 | `README.md` 본문 |
| 학습 순서 목록 | `README.md`의 `## 학습 순서` 섹션 |
| 하위그룹 카드 | `docs-manifest` |
| 이 카테고리의 예제 | `demos.yaml` — 하위 문서들의 예제를 모아서 |

마지막 블록은 3번 페이지의 "이 문서의 예제"를 카테고리 단위로 올린 것입니다. 챕터를 다 읽은 뒤 그 챕터의 예제를 한 번에 돌아보는 동선입니다.

## 5. 예제 색인 `/demo` 과 독립 열람 `/demo/…`

### 5-1. 색인 (Discovery UX & 탐색 중심 색인)

`/demo`는 241개 데모 전체를 탐색 우선(Search-First Discovery) 방식으로 재구성하여 제공합니다.

```
실습 데모 (총 241개)
[ ⌕ 데모 제목, URL, 관련 문서명 검색...                     ]
[All] [Getting Started] [Guides] [API Reference] [Architecture]      [필터 초기화]
총 241개의 데모 (페이지 1 / 11)
┌──────────────────┬──────────────────┬──────────────────┐
│ 카드 (데스크톱 3열)│ 카드             │ 카드             │
├──────────────────┼──────────────────┼──────────────────┤
│ 카드 (태블릿 2열)  │ 카드             │ 카드             │
├──────────────────┴──────────────────┴──────────────────┤
│ [이전] [1] [2] [3] ... [05] [다음]  (모바일: [이전] 1/11 [다음]) │
└────────────────────────────────────────────────────────┘
```

| 항목 | 규칙 |
|---|---|
| 표시 대상 | 241개 데모 (`demos.yaml` SSOT 기준) |
| 레이아웃 | **3/2/1 반응형 압축 그리드** (데스크톱 3열 `lg:grid-cols-3`, 태블릿 2열 `md:grid-cols-2`, 모바일 1열 `grid-cols-1`) |

### 5-2. 독립 열람

셸이 chrome을 그리고 그 안에 iframe을 담습니다 (03. 4-3).

```
┌────────────────────────────────────┐
│ [← 데모 목록] / 문서: 캐싱과 재검증     │  chrome (셸) — DemoBackButton 연동
│ use cache 기본 동작                  │  (history context 복원 또는 /demo fallback)
│ 새로고침해도 타임스탬프가 그대로인지…   │
├────────────────────────────────────┤
│                                    │  iframe
│  (데모 앱이 응답 — chrome 없음)       │  높이 브릿지 적용
│                                    │
├────────────────────────────────────┤
│ 관련 예제                            │  chrome (셸)
│ → 캐시 없이 같은 페이지 (대조)         │
└────────────────────────────────────┘
```

- **목록으로 돌아가기 (`DemoBackButton`)**: 유효한 내부 목록 탐색 context가 존재하면 `router.back()`으로 직전 `q`, `category`, `page`, 스크롤/카드 앵커 위치로 복원합니다. 직접 진입했거나 컨텍스트가 없으면 `/demo`로 안전하게 fallback합니다.
- "관련 예제"는 `doc` 필드가 같은 예제들입니다. 대조짝(캐시 켠 것 ↔ 끈 것)이 서로를 가리키게 하는 자리입니다.
- **높이 브릿지는 여기서만 씁니다.** 문서 페이지(3-2)와 랜딩(2-2)은 쓰지 않습니다.

## 6. 헤더와 검색

### 6-1. 헤더

```
nextjs docs 정독하기   docs 카테고리   예제      [⌕ 문서·예제 검색  ⌘K]  ◐  ↗GitHub
```

| 자리 | 라벨 | 링크 |
|---|---|---|
| 로고 | `nextjs docs 정독하기` | `/` |
| 메뉴 1 | `docs 카테고리` | `/#docs-categories` — 랜딩의 카테고리 섹션 |
| 메뉴 2 | `예제` | `/demo` |
| 우측 | 검색 트리거 · 테마 토글 · GitHub | — |

전 페이지 공통이며 **sticky**입니다. 좌측 트리는 헤더 아래에서 따로 스크롤합니다.

`docs 카테고리`가 별도 페이지가 아니라 랜딩의 앵커인 이유는, 03. 3-1의 URL 규칙상 **루트 `README.md`가 곧 `/`**여서 카테고리 목록 페이지를 따로 만들면 같은 내용이 두 주소를 갖기 때문입니다.

### 6-2. 화면 라벨과 도메인 용어는 다르다

화면에는 **예제**라고 쓰지만, 코드·URL·설계 문서의 용어는 **데모**입니다.

| 층 | 표기 |
|---|---|
| 화면 라벨 | 예제 |
| URL | `/demo/*`, `/zone/*`, `/demo-static/*` |
| 파일·패키지 | `demos.yaml`, `@study/demos`, `@study/demo-kit` |
| 설계 문서·ADR·용어집 | 데모 |

**이 이원화는 의도된 것입니다.** [`nextjs-app/CONTEXT.md`](../CONTEXT.md)가 "데모"를 핵심 용어로 정의하면서 `_Avoid_: 예제 앱, 샘플 앱`이라고 못박아 뒀고, 학습 문서의 4번 섹션 이름이 `예제 및 데모 설계`라 거기서 **예제 = 본문의 코드 예시**, **데모 = 실행되는 것**으로 이미 갈라져 있습니다.

전면 개명하면 ADR 3건과 URL 계약을 건드려야 하는데, 얻는 것은 라벨 하나의 일관성뿐입니다. 대신 **학습자가 읽는 문서 본문에는 "예제"라는 말이 이미 코드 예시를 가리키며 쓰이고 있으므로**, 화면 라벨은 언제나 `예제 —` 접두나 `▶` 아이콘과 함께 나타나 구별되게 합니다.

### 6-3. 검색 — UI 계약

구현(인덱싱 방식·엔진)은 미정입니다. **화면 동작만** 정합니다.

| 항목 | 정의 |
|---|---|
| 트리거 모양 | 아이콘이 아니라 **입력창 모양** + `⌘K` 뱃지. 실제 입력은 받지 않음 |
| 여는 방법 | 트리거 클릭 · `⌘K` / `Ctrl+K` · `/` (입력 요소에 포커스가 없을 때) |
| 닫는 방법 | `Esc` · 오버레이 클릭 · 결과 선택 |
| 키보드 | `↑↓` 이동 · `↵` 열기 · `⇥` 그룹 전환 |
| 결과 그룹 | **`문서` / `예제` 두 개.** 각 5개 + "더 보기" |
| 검색 대상 | 문서 제목 · 카테고리 경로 · 헤딩. **본문 전문은 1차 범위 밖** |
| 예제 필터 | `status: done`만 |
| 예제 행의 부가 정보 | zone이 아니라 **근거 문서 제목** |
| 모바일 | 트리거가 `⌕` 아이콘으로 축소 |
| 접근성 | `role="dialog"` · 포커스 트랩 · 닫을 때 트리거로 포커스 복귀 · 결과 수를 `aria-live`로 알림 |

**4개 상태를 정의합니다.**

| 상태 | 내용 |
|---|---|
| ① 닫힘 | 헤더 우측 트리거만 |
| ② 열림·입력 전 | 최근 본 문서 + 바로가기(`docs 카테고리 전체`, `예제 전체 보기`) |
| ③ 결과 | `문서` / `예제` 그룹. 일치 부분 하이라이트 |
| ④ 결과 없음 | **"이 커리큘럼은 App Router(16.3.1) 기준입니다. Pages Router API는 다루지 않습니다."** |

④의 문구를 범위 안내로 채우는 이유는, `getServerSideProps` 같은 Pages Router API를 찾다 실패하는 것이 **가장 흔한 실패 경로**일 것이기 때문입니다.

**미정으로 남기는 것**: 인덱스 생성 방식(빌드 타임 JSON / Pagefind / Orama), 한글 형태소 처리, 오타 허용.

## 7. UI 기반 — shadcn/ui

결정과 근거는 [ADR 0006](./adr/0006-shadcn-ui-as-ui-foundation.md)에 있습니다. 여기서는 결과만 씁니다.

### 7-1. 무엇을 쓰고 무엇을 안 쓰는가

| 후보 | 판정 | 이유 요약 |
|---|:---:|---|
| **shadcn/ui** | **채택** | 의존성이 아니라 소스 복사 → `@study/ui`의 Internal Package 패턴과 같은 모델. Tailwind v4 네이티브. 버전 잠김 없음 |

| 21st.dev | 참고만 | 라이브러리가 아니라 커뮤니티 카탈로그. 버전·업그레이드 개념 없음, 무료 복사 제한 있음 |

`nextra-docs-template`은 **디자인 참고**로만 씁니다 — 좌측 트리 / 우측 목차 / 브레드크럼의 비율이 이 문서의 목업에 반영돼 있습니다.

### 7-2. 화면별 컴포넌트 대응

| 화면 | 필요 | shadcn |

| 헤더 검색 팔레트 | 명령 팔레트 | `command` (cmdk) + `dialog` |
| 테마 토글 | 라이트/다크/시스템 | `dropdown-menu` |
| 좌측 문서 트리 | 접히는 다단 내비 | `collapsible` + `scroll-area` (**`sidebar`는 쓰지 않음**) |
| 모바일 좌측 트리 | 서랍 | `sheet` |
| 우측 페이지 목차 | 링크 목록 | — (자체) |
| 예제 링크 카드 | 카드 + 라벨 | `card` + `badge` |

### 7-4. 패키지 배치 — 05 A-2의 답

05. A-2가 물었던 "데모 공통 UI를 어느 패키지에 둘 것인가"가 여기서 정해집니다. **`@study/demo-kit`을 신설합니다.**

| 패키지 | 담는 것 | 쓰는 곳 |
|---|---|---|
| `@study/ui` | shadcn 컴포넌트, 헤더, 좌측 트리, 우측 목차, 카드 | **셸만** |
| `@study/demo-kit` | 기대/실제 패널, 리셋 버튼, 높이 브릿지의 데모 쪽 절반 | **데모 앱** (+ 셸은 타입만) |
| `@study/docs-render` | md → React, 코드펜스 → 링크 카드, 하이라이팅 | 셸만 |

**나눈 이유**는 `transpilePackages`입니다. `@study/ui`가 shadcn 기반 셸 전용 UI가 된 이상, 데모 앱이 그걸 의존하면 헤더·사이드바·검색 팔레트 코드까지 데모 앱의 빌드에 끌려 들어옵니다. 데모 앱은 chrome을 그리지 않는다는 규칙([`AGENTS.md`](../AGENTS.md) 12번)이 패키지 경계에서도 지켜져야 합니다.

**데모 앱에는 shadcn을 넣지 않습니다.** 데모 코드는 학습자가 읽을 코드라 군더더기가 없어야 합니다.

### 7-5. Tailwind `@source` 함정이 커진다

01. 3-4가 이미 경고한 것입니다.

```css
/* apps/shell/src/app/globals.css */
@import "tailwindcss";
@source "../../../../packages/ui";
@source "../../../../packages/docs-render";
```

이 경로가 한 단계라도 어긋나면 **빌드는 성공하고 화면도 뜨는데 공유 컴포넌트의 클래스만 조용히 누락**됩니다. 이제 UI가 전부 거기 있으므로 파급이 훨씬 큽니다 — 헤더·트리·카드가 통째로 스타일 없이 그려집니다.

데모 앱은 `@study/demo-kit`만 참조합니다.

```css
/* apps/demo-*/src/app/globals.css */
@import "tailwindcss";
@source "../../../../packages/demo-kit";
```

### 7-6. `components.json`

shadcn CLI가 파일을 어디에 쓸지 정하는 파일입니다. `@study/ui` 기준으로 잡습니다.

```json
{
  "aliases": {
    "components": "#components",
    "ui": "#components",
    "lib": "#lib",
    "hooks": "#hooks",
    "utils": "#lib/utils"
  }
}
```

`@study/ui`의 `package.json`은 `imports`/`exports` 맵을 함께 선언합니다 (shadcn monorepo 가이드 형식). 이 맵이 없으면 CLI가 경로를 못 풀고, 셸에서 `@study/ui/components/button` 형태의 import도 안 됩니다.

## 8. 디자인 토큰

### 8-1. 색

무채색 + 강조색 하나입니다. Next.js 자체가 흑백이라 색을 늘리면 학습 자료의 코드 하이라이팅과 싸웁니다.

| 역할 | 쓰임 |
|---|---|
| `background` / `foreground` | 페이지 바탕 · 본문 |
| `muted` / `muted-foreground` | 부제 · 메타 정보 · 코드블록 바탕 |
| `border` | 구분선 · 카드 테두리 |
| `primary` | CTA · 활성 트리 항목 · 검색 선택 행 |
| `accent` | 예제 링크 카드 강조 |
| `destructive` | 기대/실제 패널의 `✗` |

shadcn의 Tailwind v4 규약(`@theme inline` + oklch)을 그대로 씁니다. 토큰 이름을 새로 만들지 않습니다 — 만들면 shadcn 컴포넌트를 추가할 때마다 매핑을 손봐야 합니다.

### 8-2. 다크 모드

| 항목 | 값 |
|---|---|
| 상태 | `light` / `dark` / `system` 3상태 |
| 구현 | `next-themes`, `class` 전략 |
| **스토리지 키** | **`study_theme`** |

키 이름이 규칙입니다. 03. 6-5가 모든 zone이 동일 오리진이라 스토리지가 오염된다고 경고했고, 데모 앱에는 `demo_{슬러그}_*` 접두사를 강제했습니다. **셸도 예외가 아닙니다.** `next-themes`의 기본 키는 `theme`인데, 테마를 학습 주제로 다루는 데모가 생기면 그 순간 셸의 테마가 덮어씌워집니다.

iframe 안의 데모는 셸의 테마를 따르지 않습니다. **데모는 항상 자기 기본값으로 시작합니다** — 03. 4-7의 "데모는 초기 상태에서 시작한다"와 같은 이유이고, 테마를 주입하려면 `postMessage` 계약이 하나 더 늘어납니다.

## 10. 이 설계가 성립했다고 말할 수 있는 조건

- 랜딩의 지표 3개가 **손으로 적힌 값이 아니다** — 문서를 추가하면 저절로 바뀐다
- 대표 예제가 죽어도 랜딩 첫 화면이 비지 않는다
- 문서 페이지에 iframe이 **하나도 없다**
- 예제를 추가·삭제·이동해도 md를 고칠 일이 코드펜스가 있는 문서에만 생긴다
- 264편 전부에서 우측 목차의 항목이 같다
- 검색 결과에 zone이 **한 번도** 나타나지 않는다
- 좁은 화면에서 좌측 트리가 서랍으로 들어가고 우측 목차가 사라진다
- 데모 앱의 빌드 산출물에 헤더·검색 팔레트 코드가 들어 있지 않다
- 셸의 테마를 바꿔도 iframe 안 데모의 화면은 바뀌지 않는다
