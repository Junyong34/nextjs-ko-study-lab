# 데모 검증은 기능군이 아니라 증거와 확인 방식으로 분류한다

241개 데모는 동일한 `기대 결과 vs 실제 측정값` 구조로 검증할 수 없으므로, 데모 기능이나 사용자 조작이 아니라 확보 가능한 증거와 확인 방식을 기준으로 검증 유형을 분류한다. 데모에는 집계용 대표 유형 하나를 두되 여러 검증 항목과 서로 다른 세부 유형을 허용하며, 유효한 증거를 확보하지 못한 결과는 성공으로 대체하지 않고 `검증 불가`로 기록한다. 최종 유형은 다섯 후보 유형을 이용한 241개 전수 분석 이후 확정한다.

## Considered Options

- **모든 데모에 기대값과 실제값 비교를 유지**: UI는 단순하지만 화면 관찰, 빌드 산출물과 외부 도구 증거를 실제 측정값처럼 표현하게 된다.
- **Next.js 기능군으로 분류**: 문서 목차와는 잘 맞지만 같은 기능군 안에서도 필요한 증거와 판정 UI가 달라진다.
- **데모당 단일 검증 유형을 강제**: 집계는 쉽지만 하나의 데모에 함께 존재하는 응답 값, 전후 변화와 화면 관찰을 잃는다.

## Consequences

- 전수 분석 전에는 최종 검증 컴포넌트 API와 유형 수를 확정하지 않는다.
- 후속 구현은 대표 유형이 아니라 개별 검증 항목을 표현할 수 있어야 한다.
- 검증 불가와 환경 제약도 인벤토리에 남아 데모 재설계 또는 기대 문구 축소로 이어진다.
