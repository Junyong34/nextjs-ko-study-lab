# 문서와 데모는 md 본문의 `demo` 코드펜스 지시자로 잇는다

문서를 읽는 흐름 안에서 개념 설명 **직후**에 실습을 붙이려면 본문 안에 삽입 지점이 있어야 하고, 동시에 `nextjs-docs`의 291개 md는 GitHub에서 그대로 읽혀야 한다. 그래서 본문에 `demo` 코드펜스 블록(`zone`, `path`, `mode`, `height`, `caption`)을 두고, 셸이 렌더링할 때 이를 iframe 또는 전체 화면 링크로 치환한다. GitHub에서는 설정이 적힌 평범한 코드 블록으로 보일 뿐 아무것도 깨지지 않는다.

## Considered Options

- **frontmatter에 데모 목록**: 291개 문서의 기존 컨벤션(`# 제목` + 링크 3줄로 시작, frontmatter 없음)을 바꿔야 하고, 무엇보다 "이 문서에 데모가 있다"만 말할 수 있어 **본문 어디에 심을지 정하지 못한다.** 데모가 항상 문서 맨 끝으로 밀린다.
- **MDX + 커스텀 컴포넌트**: 표현력은 가장 높지만 `nextjs-docs`가 순수 마크다운이라는 성질을 잃고, GitHub에서 커스텀 컴포넌트가 렌더되지 않아 문서가 깨져 보인다.
- **중앙 레지스트리 패키지**: 타입 안전하고 md를 건드리지 않지만, 매핑이 문서와 다른 파일에 있어 문서를 고칠 때 같이 고쳐지지 않는다. 291개 문서 규모에서 그 표류는 시간 문제다.

## Consequences

- 이 지시자가 두 컨텍스트(학습 문서 ↔ 데모 사이트) 사이의 **유일한** 계약이 된다. 다른 결합 경로를 만들지 않는다.
- `zone`과 `path`는 문자열이라 타입 검사를 받지 못한다. 매니페스트 생성 시 존재하지 않는 zone·경로를 가리키면 빌드가 실패하도록 검증을 넣어 보완한다.
- `PROGRESS.md`의 "데모 상태" 열을 사람이 손으로 관리할 필요가 없어진다 — 문서에 지시자가 있으면 그것이 데모의 존재 증거다.
