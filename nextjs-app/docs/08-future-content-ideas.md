# 향후 콘텐츠 아이디어 백로그

문서 번역(Phase 1)과 데모 실습(Phase 2) 이후, 사이트에 지속적으로 추가할 수 있는 콘텐츠 후보를 모아둔 목록이다. 새 콘텐츠를 기획할 때 이 문서를 먼저 훑어보고 후보를 고른 뒤, 착수하는 항목은 별도의 설계 문서(`nextjs-app/docs/NN-*.md`)나 ADR로 구체화한다.

**성격**: 이 문서는 실행 계획이 아니라 **백로그**다. 각 항목은 착수 시점에 다시 조사·설계가 필요하며, 여기 적힌 내용은 방향성 메모 수준이다.

---

## 목록

### 1. 해외 기술 블로그 큐레이션 링크
각 챕터 하단에 관련 주제를 더 깊게 다루는 해외 유명/고품질 기술 블로그 링크를 연결하고, 전체를 모아보는 별도의 링크 모음집 페이지도 제공한다.
- **가치**: 공식 문서 번역만으로는 못 채우는 실무 심화·엣지케이스 갈증 해소. 사이트 체류 시간과 재방문 유도.
- **선행 작업**: 챕터별 링크를 어디에 저장할지(예: `demos.yaml`처럼 별도 YAML SSOT) 결정. 링크 품질 기준(신뢰도, 최신성) 수립. 외부 링크 깨짐(dead link) 주기 점검 체계 필요.

### 2. 기여 가이드 페이지 (컨트리뷰션 절차)
저장소에 외부 개발자가 문서 수정·번역 보완·데모 추가로 참여할 수 있도록 절차를 안내하는 페이지.
- **가치**: 1인 유지보수의 한계를 넘어 커뮤니티 기반으로 콘텐츠가 계속 늘어나는 구조를 만듦.
- **선행 작업**: PR 템플릿, 리뷰 기준, `AGENTS.md`/`CLAUDE.md` 규칙을 외부 기여자용으로 요약한 온보딩 문서, 라이선스·CLA 여부 결정.

### 3. Next.js × 외부 라이브러리 연동 가이드
zustand, TanStack Query(react-query), Prisma, next-auth 등 자주 함께 쓰는 라이브러리와의 연동 방법·주의점·꿀팁 페이지.
- **가치**: "App Router 자체"를 넘어 실제 프로젝트 구성에 필요한 정보를 제공해 실전 전환율을 높임.
- **선행 작업**: 다룰 라이브러리 우선순위 선정(사용 빈도 기준), 기존 데모 존 구조(`apps/AGENTS.md`)와의 통합 방식 검토 — 새 zone이 필요한지, 기존 zone에 데모만 추가할지.

### 4. 버전별 변경사항 트래커 (Migration/Changelog 매핑)
Next.js 마이너 버전 업데이트마다 App Router 관련 변경사항(캐싱 정책, `use cache`, PPR 등)을 챕터별로 매핑해 "이 버전에서 뭐가 바뀌었는지" 추적.
- **가치**: 특정 버전을 학습 기준으로 못박은 사이트 특성(`nextjs-docs/README.md` 기준 버전)을 살려 버전 변화에 민감한 독자층을 잡음.
- **선행 작업**: 기준 버전을 올릴 때마다(루트 `AGENTS.md` Phase Gate, `pnpm-workspace.yaml` catalog) 함께 갱신하는 프로세스 필요.

### 5. 안티패턴 / 흔한 실수 모음 (Common Pitfalls)
서버 컴포넌트에서 클라이언트 훅 오용, `revalidatePath` vs `revalidateTag` 혼동, 캐싱 관련 실수 등 실무에서 자주 겪는 트러블슈팅 사례 모음. 관련 챕터에서 링크로 연결.
- **가치**: 공식 문서가 다루지 않는 "하지 말아야 할 것"을 보완. 검색 유입(에러 메시지, 증상 기반 검색) 기대.
- **선행 작업**: 사례 수집 채널 필요(이슈, 커뮤니티 질문 등). 데모로 재현 가능한 사례는 기존 데모 표준(4단 레이아웃)에 맞춰 실습화 검토.

### 6. 인터랙티브 의사결정 플로우차트 / 치트시트
"Server Action vs Route Handler", "`fetch` 캐싱 vs `unstable_cache`/`use cache`" 같은 선택 기준을 시각적 플로우차트로 제공.
- **가치**: 텍스트보다 빠른 참조, 반복 방문 유도. 데모 앱 인프라를 활용해 시각적 임팩트를 낼 수 있음.
- **선행 작업**: shadcn/ui 기반 다이어그램/플로우차트 컴포넌트 설계 여부 결정 (`ADR 0006` — 문서 프레임워크 미사용 원칙과 정합성 확인).

### 7. 실제 프로덕션 코드 리뷰 / 케이스 스터디
오픈소스 Next.js 프로덕션 프로젝트(유명 스타터, 실제 SaaS 오픈소스 등)의 App Router 구조를 뜯어보는 코너.
- **가치**: "이론 → 예제"에서 "실전에서는 이렇게 쓴다"까지 한 단계 더 나아감.
- **선행 작업**: 대상 프로젝트 라이선스 확인(코드 인용 범위), 저작권 관련 요약·인용 가이드라인 준수 필요.

### 8. 한/영 용어집 (Glossary)
"하이드레이션", "스트리밍", "프리렌더링" 등 번역 과정에서 문서마다 표현이 갈릴 수 있는 용어를 한/영 대조로 정리.
- **가치**: 번역 일관성 유지 + 용어 검색 유입(SEO) 효과.
- **선행 작업**: 기존 `nextjs-docs/` 전체를 스캔해 용어 사용 현황 정리, 검색 UI와의 통합 여부 결정.

### 9. 성능 벤치마크 / 실습 결과 공유
동일 예제를 SSR/SSG/ISR/PPR 등 다른 렌더링 전략으로 구현했을 때의 실측 성능(Lighthouse, Web Vitals) 비교.
- **가치**: 이미 구축된 데모 앱·Vercel 배포 인프라를 활용해 차별화된 실증 콘텐츠 제공.
- **선행 작업**: [04. Vercel 배포 계획](./04-vercel-deployment-plan.md)의 실제 배포는 완료됨. 측정 재현성 확보(측정 환경 고정)만 남음.

### 10. 주간 Next.js 업데이트 큐레이션 (뉴스레터/RSS)
공식 블로그, GitHub 릴리즈, RFC 등을 짧게 요약해 정리하는 코너.
- **가치**: 콘텐츠를 지속적으로 업데이트하는 습관을 만들고 재방문을 유도하는 가장 낮은 진입장벽의 콘텐츠.
- **선행 작업**: 발행 주기와 채널(사이트 내 페이지 vs 이메일 뉴스레터 vs RSS) 결정, 자동화 여부(스크래핑/큐레이션 도구) 검토.

- **6(플로우차트)**: 데모 인프라를 활용해 시각적 임팩트를 낼 수 있어 눈에 띄는 콘텐츠가 될 수 있음.
- **9(성능 벤치마크)**: [04. Vercel 배포 계획](./04-vercel-deployment-plan.md)의 실제 배포가 끝나야 착수 가능.
