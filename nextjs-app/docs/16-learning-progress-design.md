# 학습 기록 기능 설계

Next.js 학습 사이트에서 사용자가 학습 문서와 데모를 직접 완료 표시하고, 같은 브라우저에서 그 표시를 다시 확인할 수 있게 하는 기능의 설계다. 이 기능은 학습 플래너나 분석 시스템이 아니라 개인 학습 기록 보관함이다.

관련 결정은 [ADR 0008](./adr/0008-shell-owned-client-learning-progress.md), 용어는 [데모 사이트 컨텍스트](../CONTEXT.md)에 기록한다.

## 1. 설계 목표와 비목표

### 목표

- 실제 학습 문서와 공개 데모의 완료 표시를 독립적으로 보관한다.
- 셸의 공통 UI에서 문서와 데모의 상태를 같은 방식으로 변경한다.
- 현재 문서 원본과 데모 원본을 조합해 기록 대상을 계산한다.
- 브라우저 저장소가 실패해도 학습 화면 자체는 계속 사용할 수 있게 한다.
- 사용자가 문서·데모 목록에서 완료 여부를 쉽게 확인하고 해제할 수 있게 한다.

### 비목표

- 로그인, 서버 데이터베이스, 여러 기기 간 동기화
- 방문 이력, 최근 학습, 다음 학습, 이어서 학습, 학습 순서 추천
- 학습 시간·점수·노트·복습 주기·분석 지표
- 문서 내용을 읽었는지 또는 데모를 실제로 조작했는지 자동 검증
- 전체 진행률, 카테고리별 진행률, 완료 항목 수 표시
- 피드백 제출 내용의 저장

## 2. 기록 대상과 원본 관계

기록 대상은 화면 방문으로 만들어지지 않는다. 현재 원본에서 학습 항목으로 계산된 문서와 데모만 기록 대상이다.

| 대상 | 원본 | 현재 대상 판정 | 식별자 |
|---|---|---|---|
| 학습 문서 | `nextjs-docs/docs-manifest.json`의 문서 트리·문서 목록 | 실제 사이드바 학습 메뉴에 해당하고 루트·카테고리 README가 아닌 문서 | 문서 상대 경로(`path`) |
| 데모 | `nextjs-app/packages/demos/demos.yaml` | `status: done`인 데모 | 데모 학습자 URL(`url`) |

문서 manifest에는 루트 README와 카테고리 README도 들어 있으므로, 구현 시 다음 규칙으로 학습 문서를 좁힌다.

1. 문서 트리에서 학습 메뉴로 탐색 가능한 문서 항목을 찾는다.
2. 루트 `/`와 `README.md` 또는 `*/README.md`인 카테고리 홈은 제외한다.
3. 남은 문서의 `path`, `url`, `title`, 카테고리 정보를 현재 뷰 모델에 사용한다.

데모는 `demos.yaml`의 `doc` 필드로 문서와 연결한다. 데모의 존재·제목·URL·공개 상태는 기존 [데모 목록 원본 결정](./adr/0004-demo-list-as-source-of-truth.md)을 그대로 따른다. 별도의 문서-데모 연결 설정은 추가하지 않는다.

현재 목록에 없는 저장 기록은 화면과 필터 계산에서 무시한다. 원본 데이터가 바뀌어도 다음 원칙을 따른다.

- 새 문서·새 `done` 데모: 저장 기록이 없으므로 미완료
- 제목 변경: 식별자가 같으면 기존 기록 유지
- 문서 경로·데모 URL 변경: 새 항목으로 취급
- 데모가 `done`에서 다른 상태가 됨: 화면과 계산에서 제외하되 저장 기록은 보존
- 삭제된 문서·데모: 화면과 계산에서 제외하되 저장 기록은 보존

## 3. 상태 모델

### 3-1. 완료 표시

완료 표시는 사용자의 명시적인 체크 액션으로만 생성된다.

```text
미완료
  └─ 사용자가 완료 표시
       └─ 완료 기록 저장

완료
  └─ 사용자가 다시 해제
       └─ 해당 기록 삭제
```

문서 완료 표시와 연결 데모 완료 표시는 서로 영향을 주지 않는다.

```text
문서 완료 표시  ≠  연결 데모 완료 표시
```

메뉴 전체 상태나 카테고리 상태를 별도의 도메인 상태로 저장하지 않는다. MVP 화면의 기준은 문서 항목과 데모 항목 각각의 완료 여부다.

### 3-2. 저장 포맷

```ts
type CompletedRecord = {
  completedAt: string
}

type LearningProgress = {
  version: 1
  documents: Record<string, CompletedRecord>
  demos: Record<string, CompletedRecord>
  updatedAt: string
}
```

스토리지 키는 다음 하나를 사용한다.

```text
study_learning_progress
```

저장 규칙:

- 완료한 항목만 객체에 넣는다.
- 항목이 없으면 미완료다.
- `completed: false` 항목을 미리 만들지 않는다.
- 체크 해제 시 항목을 삭제한다.
- `completedAt`과 `updatedAt`은 ISO 8601 문자열을 사용한다.
- `version`은 이후 포맷 변경을 감지하기 위한 저장 데이터 버전이다.
- `updatedAt`과 완료일은 MVP 화면에서 수치 진행률 대신 사용하지 않는다.

## 4. 상태 소유와 화면 경계

### 셸의 책임

- 현재 문서·데모 목록을 읽고 기록 대상 뷰 모델을 만든다.
- localStorage 읽기·쓰기·검증·예외 처리를 담당한다.
- 문서와 데모의 완료 표시 상태를 하나의 클라이언트 상태로 제공한다.
- Drawer, 문서 상세 화면, 데모 독립 열람 chrome, 전체 기록 페이지를 연결한다.

### 데모 앱의 책임

- 실제 Next.js 기능을 실행하고 검증한다.
- 학습 기록 상태를 읽거나 쓰지 않는다.
- 완료 표시 UI를 자체 chrome이나 iframe 내부에 추가하지 않는다.

같은 데모가 여러 셸 화면에 나타나면 `url`이 같은 한 기록을 공유한다. 문서의 연결 데모 카드, 데모 색인 카드, 독립 열람 셸은 동일한 데모 상태를 읽을 수 있지만, 카드 자체는 탐색과 상태 확인을 담당하고 완료 변경은 상세 화면과 전체 기록 페이지에서 제공한다.

## 5. 저장소 예외와 동기화

### 읽기

- 서버 렌더링 중에는 localStorage에 접근하지 않는다.
- 클라이언트에서 키를 읽어 런타임 스키마를 검증한다.
- 키가 없으면 빈 기록으로 시작한다.
- JSON 파싱 또는 스키마 검증에 실패하면 저장 데이터를 무시하고 빈 기록으로 복구한다.
- 복구가 발생하면 Drawer 또는 전체 기록 페이지에 비차단 안내를 표시한다.

### 쓰기

- `setItem` 실패를 예외로 전파하지 않는다.
- 메모리 상태는 갱신해 현재 탭의 화면 조작을 허용한다.
- 저장이 보장되지 않는다는 안내를 사용자에게 표시한다.

### 여러 탭

- `study_learning_progress`의 `storage` 이벤트를 구독한다.
- 다른 탭에서 유효한 기록이 저장되면 현재 탭의 상태를 다시 계산한다.
- 동시에 변경되면 마지막으로 저장된 값을 사용한다.
- 별도의 병합 UI나 충돌 해결 시스템은 만들지 않는다.

기존 데모 색인 복원용 `study_demo_list_context`는 `sessionStorage` 기반 탐색 복원 데이터이므로 학습 기록과 합치지 않는다.

## 6. UI 구조

### 6-1. 플로팅 버튼과 Drawer

셸이 렌더링하는 주요 화면 전체에 우측 하단 플로팅 버튼을 표시한다. 데모 iframe 내부에는 표시하지 않는다.

Drawer는 요약 대시보드가 아니라 학습 기록 메뉴다.

```text
학습 기록

문서 기록 보기
데모 기록 보기
전체 학습 기록

피드백 보내기
```

다음 요소는 Drawer에서 제거한다.

- 전체 진행률
- 완료 숫자와 분모
- 카테고리별 숫자
- 최근 학습
- 다음 학습
- 이어서 학습하기 CTA

### 6-2. 전체 기록 페이지

경로는 `/study-progress`로 한다. 이 페이지는 문서 콘텐츠가 아니므로 문서 사이드바 트리와 우측 문서 목차를 사용하지 않는 전용 셸 화면으로 구성한다.

```text
학습 기록

[문서] [데모]

[전체] [완료] [미완료]
[카테고리 선택]
[검색]

문서 또는 데모 목록
  └─ 각 항목의 완료 표시 / 해제

전체 학습 기록 초기화
```

기본 필터는 `전체`다. 필터는 기록 데이터와 별개인 화면 상태이며, MVP에서는 localStorage에 저장하지 않는다.

목록에는 완료 숫자나 퍼센트를 표시하지 않는다. 각 항목에만 체크 아이콘, `완료` 배지, 또는 미완료 상태를 표시한다.

완료 기록이 하나도 없을 때도 전체 목록은 미완료 상태로 표시한다. 목록을 숨기지 않고 다음 안내만 추가한다.

```text
아직 표시한 학습 기록이 없습니다.
```

### 6-3. 완료 표시 위치

| 화면 | 완료 표시 변경 | 비고 |
|---|---:|---|
| 문서 상세 페이지 | 가능 | `이 문서를 학습 완료로 표시` |
| 데모 독립 열람 셸 | 가능 | iframe 바깥의 셸 chrome에서 제공 |
| `/study-progress` 문서 목록 | 가능 | 문서 기록의 직접 변경 지점 |
| `/study-progress` 데모 목록 | 가능 | 데모 기록의 직접 변경 지점 |
| 문서·데모 카드 | 불가 | 현재 상태만 표시하고 링크 탐색 담당 |

문구는 시스템이 학습을 검증했다는 인상을 주지 않도록 `학습 완료로 표시`를 기본 표현으로 사용한다.

### 6-4. 반응형과 접근성

- 데스크톱: 우측 Drawer
- 모바일: 화면 폭 대부분을 차지하는 우측 패널
- 배경 오버레이와 닫기 버튼 제공
- `Escape`로 닫기
- 열릴 때 Drawer로 포커스 이동
- 닫힐 때 플로팅 버튼으로 포커스 복원
- 완료 표시 컨트롤은 키보드로 조작 가능
- 저장 불가 안내는 사라지는 토스트에만 의존하지 않고 Drawer 또는 페이지에 남김

## 7. 초기화와 피드백

### 전체 초기화

`/study-progress`에서 전체 학습 기록 초기화를 제공한다.

- 문서와 데모 완료 기록을 모두 삭제
- 확인 대화상자 필수
- 취소 시 상태 유지
- 초기화 후 모든 항목은 미완료
- 카테고리별 초기화와 별도 일괄 선택 해제는 MVP에서 제공하지 않음

개별 항목은 각 완료 표시를 다시 해제하는 방식으로 초기화한다.

### 피드백

새로운 피드백 저장 기능은 만들지 않는다. Drawer 하단에서 기존 `@study/ui`의 `FeedbackTrigger`를 재사용하고, 현재의 mailto 기반 제출 흐름을 유지한다. 피드백 제출 여부는 학습 기록에 영향을 주지 않는다.

## 8. 검증 기준

### 상태·저장

- 빈 localStorage에서 모든 대상이 미완료로 보인다.
- 문서 체크는 해당 문서만 완료로 만든다.
- 데모 체크는 해당 데모만 완료로 만든다.
- 문서 체크와 데모 체크는 서로 자동 전파되지 않는다.
- 체크 해제 시 해당 저장 항목이 삭제된다.
- 새로 추가된 문서·`done` 데모는 저장 기록 없이 미완료로 보인다.
- 제목 변경은 기록을 유지한다.
- 현재 원본에 없는 기록은 화면에 나타나지 않는다.
- 잘못된 데이터와 localStorage 접근 실패가 화면 전체를 중단시키지 않는다.
- 여러 탭의 변경이 `storage` 이벤트로 반영된다.

### UI·원본 연결

- 카테고리 README와 랜딩은 기록 대상에 포함되지 않는다.
- `status: done`이 아닌 데모는 기록 대상에 포함되지 않는다.
- 같은 데모 URL이 여러 화면에서 하나의 상태를 공유한다.
- Drawer에 숫자 진행률이나 추천 문구가 나타나지 않는다.
- `/study-progress`가 문서 사이드바 트리에 나타나지 않는다.
- 검색·카테고리·완료 상태 필터가 문서와 데모 탭에서 각각 동작한다.
- 키보드만으로 Drawer 열기·닫기와 완료 표시가 가능하다.

## 9. 후속 확장 후보

다음 항목은 이번 설계에 포함하지 않는다.

- 로그인 기반 서버 저장과 여러 기기 동기화
- 학습 노트·메모
- 자동 복습·추천·학습 순서
- 완료일을 활용한 기록 정렬·통계
- 카테고리별 집계와 시각화
- 외부 폼 또는 GitHub Issue API 연동
