# 데모 사이트 컨텍스트

학습 문서를 화면에 그리고 각 개념의 데모를 실행하는 사이트의 용어를 정의합니다. 구현 방법이 아니라 이 사이트가 다루는 개념과 경계를 기록합니다.

`데모`, `학습 문서`, `메뉴 페이지`, `학습 카테고리`는 [학습 문서 컨텍스트](../nextjs-docs/CONTEXT.md)에 정의돼 있으며 여기서 재정의하지 않습니다.

## Language

**zone**:
자기 `next.config`를 온전히 소유하는 하나의 독립 Next.js 앱입니다. 학습자에게는 사이트의 일부로 보이지만 빌드와 배포는 따로 이뤄집니다.
_Avoid_: 서브앱, 모듈, 마이크로 프론트엔드

**셸**:
학습자의 모든 요청을 가장 먼저 받아 학습 문서를 그리고, 자기 것이 아닌 경로를 다른 zone으로 넘기는 zone입니다. 사이트에 정문은 하나뿐입니다.
_Avoid_: 호스트, 게이트웨이, 메인 앱, 컨테이너 앱

**데모 앱**:
셸이 아닌 zone. 하나 이상의 데모를 실행하는 것만이 존재 이유이며 학습 문서를 그리지 않습니다.
_Avoid_: 예제 앱, 샘플 앱

**설정 축**:
한 앱 안에 동시에 존재할 수 없는 전역 설정의 대립쌍입니다. zone을 가르는 유일한 기준이며, 학습 카테고리는 zone 경계가 아닙니다.
_Avoid_: 기능 그룹, 데모 카테고리

**데모 목록**:
데모의 존재·주소·상태·제목·근거 문서·zone을 선언하는 단일 원본입니다. 어떤 데모가 있는지는 오직 여기서 정해집니다 ([ADR 0004](./docs/adr/0004-demo-list-as-source-of-truth.md)).
_Avoid_: 레지스트리, 매니페스트, 카탈로그, 인덱스

**데모 지시자**:
학습 문서 본문에 두어 그 지점에서 어떤 데모를 가리킬지 지정하는 표기입니다. **위치만** 정하며, 데모의 존재를 만들지는 않습니다. 렌더 결과는 iframe이 아니라 링크 카드입니다.
_Avoid_: 임베드 태그, 숏코드

**독립 열람**:
학습 문서를 거치지 않고 데모 하나만 보는 방식입니다. 셸이 제목·설명·문서 링크를 그리고 그 안에 데모를 담습니다. **데모를 보는 유일한 방식**이며, 문서 본문에서는 링크로만 가리킵니다 ([06. 3-2](./docs/06-ui-and-screen-design.md)).
_Avoid_: 단독 페이지, 스탠드얼론

**진입점**:
데모 목록의 URL이 가리키는, 그 데모가 시작되는 하나의 주소입니다. 여러 라우트를 오가는 데모도 진입점은 하나입니다.
_Avoid_: 시작 페이지, 랜딩

**데모 상태**:
`stub`(주소만 정해짐) · `wip`(만드는 중) · `done`(공개됨) 세 값입니다. 학습자에게 보이는 것은 `done`뿐입니다.
_Avoid_: 진행률, 완료 여부

**기준 버전**:
학습 문서가 근거로 삼는 Next.js 버전이자 모든 zone이 설치하는 버전입니다. 두 값은 언제나 하나입니다.
_Avoid_: 최신 버전, 지원 버전, 권장 버전

**대표 데모**:
랜딩 히어로에 iframe으로 띄우는 데모 하나입니다. `demos.yaml`의 `featured`가 지정하며 전체에서 최대 1개입니다. **문서 본문에 데모를 심지 않는다는 규칙의 유일한 예외**입니다 ([06. 2-2](./docs/06-ui-and-screen-design.md)).
_Avoid_: 인라인 데모, 미리보기, 프리뷰

**예제 (화면 라벨)**:
학습자 화면에서 **데모**를 가리키는 말입니다. URL·파일·설계 문서에서는 계속 `데모`를 씁니다. 학습 문서 본문의 "예제"는 다른 뜻(코드 예시)이므로, 화면 라벨은 `▶` 아이콘이나 `예제 —` 접두와 함께 나타냅니다 ([06. 6-2](./docs/06-ui-and-screen-design.md)).
_Avoid_: 이 말을 코드·URL·ADR에 쓰는 것

## 학습 기록 컨텍스트

**학습 기록**:
학습자가 자신이 학습했다고 판단한 학습 문서와 데모에 남기는 개인 기록입니다. 시스템이 실제 학습 여부를 검증하거나 학습 순서를 지시하는 기능이 아닙니다.
_Avoid_: 자동 진도, 학습 분석, 학습 추천

**완료 표시**:
학습자가 문서 또는 데모를 학습했다고 스스로 판단해 남기는 명시적 표시입니다. 문서의 완료 표시와 연결된 데모의 완료 표시는 서로 독립적입니다.
_Avoid_: 방문 기록, 자동 완료, 검증 완료

**학습 기록 대상**:
사이트의 실제 학습 메뉴로 노출되는 학습 문서와 공개된(`done`) 데모입니다. 랜딩, 카테고리 홈, 데모 색인, 데모 독립 열람 자체는 학습 기록 대상이 아닙니다.
_Avoid_: 모든 URL, 페이지 방문 목록, 카테고리 진행률

## 이커머스 도메인 표준 컨셉

데모는 학습자가 실제 프로덕션 상황을 쉽게 체감할 수 있도록 **이커머스 플랫폼**을 공통 비유 도메인으로 사용합니다.

**상품 카탈로그 (Catalog / Products)**:
상품 목록, 카테고리 필터링/정렬(`searchParams`), 상품 상세(Dynamic Routes `[id]`), 이미지 최적화(`<Image>`), 상품 리뷰/추천 스트리밍(`Suspense`), ISR 및 `use cache` 기반 캐싱과 태그 무효화의 표준 시나리오입니다.

**장바구니 및 주문 (Cart & Checkout)**:
장바구니 담기/수량 변경(Server Actions, Optimistic Updates), 배송지/쿠폰 폼 검증(`useActionState`, `<Form>`), 결제 프로세스 및 완료 리다이렉트(`redirect`, `catchError`)의 표준 시나리오입니다.

**회원 및 인증 (Auth & Account)**:
로그인/로그아웃 폼, 세션 쿠키(`cookies()`), 권한 가드(Middleware, `forbidden`, `unauthorized`), 로그인 모달(Parallel & Intercepting Routes), 마이페이지의 표준 시나리오입니다.

**관리자 및 대시보드 (Admin / Analytics)**:
실시간 재고/매출 모니터링(Streaming, Client Fetching: SWR / TanStack Query), 상품 등록/수정(Draft Mode, Server Actions), Route Handlers(REST API / Webhook), Web Vitals 리포팅의 표준 시나리오입니다.

## 데모 검증 컨텍스트

**검증 항목**:
가이드의 한 절차를 수행한 뒤 하나의 기대 결과와 하나의 증거로 확인하는 최소 단위입니다. 한 데모는 여러 검증 항목을 가질 수 있습니다.
_Avoid_: 검증 문구, 성공 메시지

**검증 유형**:
검증 항목이 사용하는 증거와 확인 방식의 분류입니다. Next.js 기능군이나 사용자 조작 방식은 검증 유형이 아닙니다.
_Avoid_: 기능 유형, 데모 카테고리

**대표 검증 유형**:
한 데모의 검증 항목 가운데 집계와 후속 작업 배치를 대표하는 유형 하나입니다. 데모 안의 다른 검증 유형을 배제하지 않습니다.
_Avoid_: 단일 검증 유형, 데모 유형

**검증 증거**:
기대 결과가 실제로 발생했는지 확인할 때 근거로 삼는 값, 변화, 화면 상태 또는 산출물입니다.
_Avoid_: 완료 문구, 성공 설명

**증거 위치**:
검증 증거를 확인하는 데모 화면, URL, Network, 콘솔, 서버 로그, 소스, 빌드 산출물 또는 배포 환경입니다. 위치가 다르다는 이유만으로 검증 유형이 달라지지는 않습니다.
_Avoid_: 검증 유형

**화면 관찰**:
자동 판정값을 만들지 않고 가이드가 지정한 화면 변화와 성공 단서를 학습자가 직접 확인하는 검증 방식입니다.
_Avoid_: 수동 통과, 눈대중 검증

**검증 불가**:
현재 데모와 실행 환경에서 기대 결과를 뒷받침할 유효한 증거를 확보할 수 없는 분석 결과입니다. 검증 유형이나 성공 상태가 아닙니다.
_Avoid_: 적용 대상 아님, 간주 통과

**전수 검증**:
241개 데모의 가이드 절차를 실제로 수행하고 증거, 결과와 네 섹션의 수정 필요 여부를 빠짐없이 기록하는 점검입니다.
_Avoid_: 샘플링, 정적 검사

## 데모 3단계 안내 구조

**1단계: 개념 핵심 요약 및 보완 해설**:
공식 문서의 추상적인 설명을 알기 쉽게 풀어서 설명하고, 왜 이 기능이 필요한지 배경과 핵심 개념을 짚어주는 영역입니다.

**2단계: 단계별 체험 절차**:
학습자가 데모 화면에서 어떤 버튼을 누르고 어떤 옵션을 변경해야 하는지 Step 1, Step 2 순으로 명확히 안내하는 가이드 영역입니다.

**3단계: 기대값 vs 실제값 검증 패널**:
조작 후 화면과 내부 상태(캐시 ID, 타임스탬프, 서버 응답 등)가 기대한 대로 변경되었는지 `ExpectedActualPanel`과 실시간 로그로 시각 검증하는 영역입니다.
